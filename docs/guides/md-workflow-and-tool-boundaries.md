# MD 模拟工作流程与工具边界指南

## 1. 先说结论：我们应该做什么，不应该重写什么

MateriaSim 应当成为“研究定义、模型资产、场景构建、协议选择、执行和证据管理”的组织层，而不是重新实现一个 GROMACS。

- **交给 GROMACS**：其支持范围内的能量和力计算、积分、温压耦合、约束、长程静电、CPU/GPU 数值计算，以及已有的预处理和分析工具。
- **复用外部工具**：分子参数化、聚合物结构生成、几何装填、晶体／表面构建和通用轨迹分析。按任务选择，不要求全部安装。
- **我们自己维护**：材料与模型的明确描述、工具适配、组成换算、场景规则、完整输入交接、参数兼容检查、协议资产、研究批次、质量检查和可追溯结果。
- **需要科研判断**：模型是否适合目标性质、交叉相互作用是否可靠、采样是否充分，以及结果如何与实验比较。这些不能靠一个软件开关自动完成。

因此，“补功能”通常是接入成熟工具并补上校验和业务语义，不是自行编写积分器、通用参数拟合程序或几何装填算法。GROMACS 官方也明确指出：体系准备会随研究问题和模型物理而变化，有些步骤是可选的。[官方体系准备指南](https://manual.gromacs.org/current/user-guide/system-preparation.html)

### 本文如何区分证据

1. **上游能力**：来自下文链接的 GROMACS 官方手册、开源项目维护者文档或仓库；查阅日期为 2026-09-16，GROMACS `current` 页面显示 2026.3。
2. **本项目现状**：来自本次读取的源码、配置、README 和使用指南，基线提交为 `784080f`。历史实测状态不等于本轮重新验收。
3. **建议接入**：本文针对 MateriaSim 的设计判断，不是已经交付的接口、配置字段或科学批准。

上游 `current`／`stable`／默认分支会变化；正式接入必须锁定实际版本并测试，不能直接照搬最新文档中的安装组合。本文未安装工具、未修改科学参数，也未运行 MD。

## 2. 一个完整流程，以及每一步的责任

```text
研究问题与目标性质
        ↓
化学身份、分辨率和模型路线选择
        ↓
组分结构＋拓扑／参数准备 ← 材料类型决定不同准备路线
        ↓
交叉作用审查＋组成解析＋场景装配 ← 溶液／固体／界面等路线不同
        ↓
最终体系核对＋grompp 预处理
        ↓
最小化与场景适用的平衡过程
        ↓
生产采样＋检查点／资源管理
        ↓
目标性质分析＋不确定性＋基准比较
        ↓
归档；不足则形成有记录的新验证或采样任务
```

共享的是交接与证据结构，不是所有任务都执行同一套“加水→NVT→NPT→水化分析”。

| 阶段 | GROMACS 自带什么 | 可复用的外部能力 | MateriaSim 应负责什么 |
|---|---|---|---|
| 研究定义 | 不替研究者选择科学问题 | 相关体系的论文、实验与模型资料 | 明确组成、场景、变量、观察量、对照和预算 |
| 分子结构／参数准备 | `pdb2gmx` 根据已有残基与力场数据库生成拓扑、加氢等；不是任意化学结构参数化器 | ACPYPE／AmberTools、OpenFF、polyply、mBuild/Foyer 等候选路线 | 保存化学身份、参数来源、构建配方和模型版本；检查缺失与适用范围 |
| 几何与体系装配 | `editconf`、`insert-molecules`、`genconf`、`solvate`、`genion` | Packmol；聚合物、晶体／表面的专门生成工具 | 把明确组成和几何意图转换为工具输入；同步拓扑、映射与实际计数 |
| 原生预处理 | `grompp` 展开拓扑、处理 MDP 并生成 TPR | 通常无需另一套编译器 | 冻结完整输入闭包、保存有效参数、核对原子顺序和编译结果 |
| 最小化／平衡／采样 | `mdrun` 执行选定算法和物理参数 | 特殊采样仅按具体课题另选 | 选择经审查的协议、交接状态、检查目标完成情况；不自动修改模型救活任务 |
| 中断与恢复 | 原生检查点、续跑、输出校验 | 服务器调度、存储备份 | 任务身份、单写者、预算、失败保留和恢复授权 |
| 分析与统计 | 能量、RDF、MSD、链尺寸等；部分工具已有误差估计 | MDAnalysis、PyMBAR、physical_validation 等 | 输入角色、选择语义、单位、窗口、方法适用性、跨重复比较与证据封装 |
| 科学交付 | 原生数据和日志 | 实验／文献基准 | 区分工程成功、物理数值质量、采样质量与模型适用性；完整保存失败与局限 |

上述原生准备与编译职责分别见 [pdb2gmx](https://manual.gromacs.org/current/onlinehelp/gmx-pdb2gmx.html)、[体系准备](https://manual.gromacs.org/current/user-guide/system-preparation.html)及 [grompp](https://manual.gromacs.org/current/onlinehelp/gmx-grompp.html)。这张表不表示 MateriaSim 已经封装表中全部命令。

## 3. 科学配置要分成六部分，不只是调 MDP

### 3.1 组分身份与模型：模拟的到底是什么

建议每个可复用模型都能回答以下问题；尚未有对应程序字段的信息，先保存在模型说明和来源资产中，不向当前严格 JSON 随意追加字段。

| 类型 | 必须明确的信息示例 |
|---|---|
| 小分子／溶剂／离子 | 化学结构、立体化学、键级、质子化／互变异构状态、净电荷、坐标和拓扑身份 |
| 合成聚合物 | 单体、连接位点、链长、端基、共聚序列、立构规整性；多分散时各链型的明确分布 |
| 蛋白质等生物大分子 | 序列与结构来源、缺失残基／原子、链、端基、二硫键、辅因子和修饰 |
| 纳米颗粒／表面 | 材质、晶型、尺寸、晶面、表面终止／修饰／电荷；是刚性、受约束还是可变形模型 |
| 交联网络 | 明确交联连接、端基处理、连通性和缺陷；不能只记录一个“交联比例”代替实际网络 |

**结构文件不等于完整力场模型。** 坐标描述位置，拓扑与参数描述连接和相互作用；能够读入 PDB/GRO 并不代表已得到适用于模拟的参数。`pdb2gmx` 依赖选定力场的数据库，因此生物大分子中的未知残基或修饰也可能需要额外准备。[pdb2gmx 官方说明](https://manual.gromacs.org/current/onlinehelp/gmx-pdb2gmx.html)

### 3.2 相互作用包：一起用什么物理模型

同一体系的参数需要作为一个相容组合审查，不能把每个组分分别“参数化成功”当作整体已可靠。

至少核对：力场家族和版本、分辨率、电荷约定、水／离子模型、非键函数与组合规则、1–4 缩放、排除规则、显式交叉参数和必要的约束／虚拟位点。GROMACS 拓扑本身包含 `defaults`、`atomtypes`、`nonbond_params`、`moleculetype` 等机制；我们要审查和正确生成这些内容，不另造一个力计算系统。[拓扑文件格式](https://manual.gromacs.org/current/reference-manual/topologies/topology-file-formats.html)

MateriaSim 的相互作用包应记录“哪些精确模型组合，在什么条件与性质范围内被验证”，而不只是一个力场名字。目前的 `engineering_only` 只支持工程用途声明；进入正式用途仍需真实参数、协议和适用性证据。[当前用途检查](../../src/materiasim/specs/purpose.py)

### 3.3 组成与场景：数量、几何、相态是不同信息

- 组成：每种模型的分子数／链数／颗粒数，或有明确换算定义的浓度、质量分数、摩尔分数。
- 几何：盒矢量、周期方向、表面法向、填充区域、排除区域和初始距离。
- 场景：均匀溶液、单链、熔体、晶体、薄膜、固液界面等。
- 制备过程：从什么初态，经过什么平衡路径得到目标状态。

数量必须最终解析为整数，并保存请求值、实际值、换算依据及偏差。以摩尔浓度为例：

\[
N_i \approx c_i N_A V,\qquad V[\mathrm{L}]=V[\mathrm{nm}^3]\times10^{-24}.
\]

这是数量换算关系，不是本项目当前已有的浓度接口。整数化、电中性、其他溶质和实际体积必须联合检查；NPT 后体积会变化，初始按盒体积得到的浓度不等于最终平均浓度。质量分数不能直接当成分子数分数，目标密度也不是装填成功就自动成立。

特别注意两个原生工具的真实边界：

- `gmx solvate` **不只支持水**，也能使用其他溶剂或混合溶剂坐标盒；但要求合适的输入组织，裁掉重叠分子后仍需核对最终组成。溶剂的坐标模板与其拓扑所指定的水模型不能混为一谈。[solvate 文档](https://manual.gromacs.org/current/onlinehelp/gmx-solvate.html)
- `gmx genion` 主要通过替换溶剂分子放入单原子离子。较大多原子离子应考虑其他装配方式；`-conc` 不扣除已有离子，`-neutral` 还会额外加中和离子。因此平台必须核算最终离子组成，不能盲传一个浓度。[genion 文档](https://manual.gromacs.org/current/onlinehelp/gmx-genion.html)

### 3.4 协议：物理参数由 GROMACS 执行，选择依据由研究者负责

协议至少明确最小化方法、动力学系综、温压目标、耦合方式、约束、步长、非键处理、阶段状态继承以及采样间隔。GROMACS 已有相关算法和 MDP 配置，不需要我们重写；但要选择与力场和场景一致的组合。[MDP 参考](https://manual.gromacs.org/current/user-guide/mdp-options.html)

建议维护“有适用条件的协议模板”，而不是按材料名字复制 runner。相同物理流程可换材料和数量；不同边界、制备历史或观察量可能必须换协议。模板是经审查的起点，不是全材料通用默认值。

### 3.5 观察量：先决定测什么，再决定保存什么

研究设计应反向决定输出数据：温度／密度等需要合适的能量记录；链构象需要拓扑连接和坐标；某些动力学方法还需要更密的时间采样或速度。不能在只保存稀疏坐标后，声称可以恢复未保存的速度／力。

### 3.6 执行环境：与科学模型分开

CPU/GPU、线程、作业时限、磁盘预算和工具路径属于执行配置，不属于分子模型。CPU 可以做小任务的正式计算；GPU 主要改变可承担的规模和耗时，不自动提高模型可靠性。具体卸载选项取决于 GROMACS 构建、硬件及模拟设置。[GROMACS 性能指南](https://manual.gromacs.org/current/user-guide/mdrun-performance.html)

## 4. 不同组分和场景，应走什么路线

以下是**设计路线，不是可直接提交到当前 CLI 的新场景名称，也不是未经体系验证即可照抄的生产协议**。每条路线都需要上一节的模型与参数检查。

### A. 小分子：孤立分子、单溶质与多组分溶液

- 孤立分子：准备结构／参数，选择真正非周期或有明确镜像误差控制的模型，再做最小化及所需动力学；不加水，不机械加入 NPT。当前无水周期盒不等于这条路线。
- 单溶质水溶液：溶质参数准备→盒与溶剂→必要的离子→最终核对→最小化→适用的温度／密度平衡→生产采样。
- 多组分／混合溶剂：先联合审查模型和组成，再使用显式数量装填或合适的混合溶剂盒；装填后重新核对数量、电荷、体积和空间重叠。
- 对均匀液体可考虑密度、组分 RDF、扩散等验证；若研究相分离，必须额外设计尺度、初态与采样判断，不能把初始分区装填等同于平衡相分离。

原生工具可解决部分装配，复杂几何可复用 Packmol；Packmol 接受单分子模板、数量和区域限制，提供初始坐标，不负责力场、化学反应或平衡判定。[Packmol 官方仓库](https://github.com/m3g/packmol)

### B. 蛋白质等生物大分子溶液

- 先处理结构缺失、残基／端基、质子化、二硫键、辅因子与修饰；已有残基可利用 `pdb2gmx` 路线，未知部分单独处理。
- 大分子与小分子分别准备后，还需审查组合兼容；不能认为蛋白力场会自动参数化任意配体。
- 按研究目的设计约束释放和平衡；检查局部与整体构象，不以短时间 RMSD 稳定代替全部慢自由度采样充分。
- 对 MateriaSim 而言，这需要模型导入与映射、所需拓扑特征、约束资产和分析接入；不是现有 ZIL 模板换一个文件名。

这一准备路线基于 GROMACS 的残基数据库机制，而不是任意分子通用自动识别。[pdb2gmx 官方说明](https://manual.gromacs.org/current/onlinehelp/gmx-pdb2gmx.html)

### C. 合成聚合物单链、聚合物溶液与熔体

- 单链：从单体／连接规则生成目标链的拓扑和构象；明确真空、隐含环境或显式溶剂，不能统一当成水盒。
- 溶液：生成各链→按链数、链型及溶剂组成装配→处理必要离子→排除不合理近接→平衡→采样链尺寸和溶剂／链间作用。
- 熔体：不加溶剂；生成足够数量与尺寸的链，采用适合该材料的致密化与松弛方案，记录制备历史。初始密度达到目标不证明链构象或缠结已平衡。
- 若采用升温／降温、约束释放或其他预平衡技术，必须单独记录适用依据和动力学解释限制，不能由 agent 为了跑通自动添加。

优先评估 polyply：它可依据已有库或用户定义的构建块生成聚合物输入和坐标，也有原子级与粗粒化路线。但它不会自动提供所有单体的可靠参数；生成的模型和构象仍需验证。[polyply 官方仓库](https://github.com/marrink-lab/polyply_1.0)

若研究交联凝胶，应区分“事先生成固定网络，再模拟其性质”与“模拟真实聚合／交联反应”。前者需要网络生成及拓扑检查，后者需要适用的反应模型；普通固定拓扑不能通过增加步数自动生成化学键。

### D. 晶体、无定形固体与薄膜

- 晶体：由可靠晶体结构生成超胞／取向，选择能描述该材料的相互作用模型，再验证结构、应力和目标性质。
- 无定形材料：必须记录初态与制备历史；如采用熔融／冷却过程，还要说明速率和模型适用范围。
- 自由表面／薄膜：先定义哪些方向周期、是否含真空层或墙面、哪些自由度允许变化，再确定压力耦合与约束。
- 不把所有固体都送入各向同性 NPT；也不能把当前 `packed_zil_dry` 的无水固定体积短测称为固相支持。

晶体和表面结构可评估 pymatgen 等材料工具，但得到结构不等于获得 GROMACS 力场。[pymatgen 官方仓库](https://github.com/materialsproject/pymatgen)

### E. 纳米材料／固液界面

- 先定义颗粒或基底的表面化学、有效模型和自由度；其后才是溶液组分装配。
- 先审查颗粒／表面与溶剂、离子、聚合物之间的相互作用，再逐步引入组分；几何接触不等于共价接枝。
- 对薄层带电体系，应专门评估静电边界及镜像影响。GROMACS 有 `ewald-geometry=3dc` 等机制，但它仍是在三维倒空间求和上加修正，并非把任意体系简单改成二维；也不是所有界面都必须使用该设置。[静电几何选项](https://manual.gromacs.org/current/user-guide/mdp-options.html)
- 分析需匹配几何：密度剖面、表面距离、面内／法向运动等可能比整体均匀液体 RDF 更合适。均匀体系的归一化不能直接套给有大量真空或不可达区域的体系。[RDF 归一化与表面选项](https://manual.gromacs.org/current/onlinehelp/gmx-rdf.html)

### F. 聚合物＋纳米材料＋小分子＋溶剂

这不是再写一个独立的“超级 runner”，而是组合已验证的模型与场景能力：

1. 确定整体相容的模型路线、分辨率和研究目标。
2. 准备聚合物链、颗粒／基底、小分子和溶剂模型。
3. 核对交叉作用；设计单组分、关键成对组合及整体体系的验证，按问题选择对照而非机械穷举。
4. 先建立固定几何／大结构，再填入其他组分，核对数量、拓扑、连接与周期距离。
5. 使用该场景专属的松弛和采样协议；分析特定作用，不强制全部做水化。

这是本文建议的接入方式。当前 MateriaSim 尚不能直接完成此完整组合。

### G. 什么时候应重新考虑引擎，而不是继续改 GROMACS 配置

若目标模型需要金属多体势、反应性断键成键等，先核查所需势函数及其实现，而不是因为“材料很大”就换引擎，或把新材料硬塞进现有 GAFF 模板。

例如 LAMMPS 官方提供 EAM 和 ReaxFF 路线；这说明存在可评估的成熟实现，并不说明任意金属＋有机物组合已有可靠交叉参数，也不构成现在就接入第二引擎的要求。[EAM](https://docs.lammps.org/pair_eam.html)、[ReaxFF](https://docs.lammps.org/pair_reaxff.html)

原子级和粗粒化也不能随意混合。polyply 能生成粗粒化输入，不代表本项目已经支持；当前后端明确拒绝粗粒化模型。[本项目原生适用性检查](../../src/materiasim/engines/gromacs/specification.py)

## 5. 值得复用的开源工具，以及我们实际需要写的部分

“靠谱”在这里指有可查的维护者文档、公开实现与测试／论文依据，不是对任意材料、任意版本组合的适用保证。以下除既有 Packmol／MDAnalysis 路线外，均是候选，不是本轮安装清单。

| 工具与原始来源 | 适合复用的能力 | 我们需要写的接入／约束 | 当前选择建议 |
|---|---|---|---|
| [Packmol](https://github.com/m3g/packmol) | 按数量与空间条件装填分子 | 配方解析、区域生成、种子记录、单位转换、实际几何和数量检查；不重写装填优化算法 | 保留已有适配，先扩混合溶剂等具体需求 |
| [ACPYPE](https://github.com/alanwilter/acpype) | 调用 Antechamber 生成／转换分子拓扑，包含 GROMACS 输出 | 明确化学输入、电荷方法与 GAFF 版本，收集完整资产和日志；核对导出后的参数 | 与现有 GAFF 路线相近，优先评估；不是直接批准所有新分子 |
| [OpenFF Interchange](https://github.com/openforcefield/openff-interchange) | 与 OpenFF Toolkit 配合，保存参数化体系并导出 GROMACS 等格式 | 记录所选力场、化学范围与转换支持范围；对关键项做能量／参数一致性检查 | 作为另一条明确参数路线，不与现有 GAFF 默认混用 |
| [polyply](https://github.com/marrink-lab/polyply_1.0) | 按库或用户构建块生成聚合物拓扑与坐标 | 链型／端基／序列定义、库覆盖检查、生成记录与交接；额外所需参数由研究提供 | 聚合物接入优先候选；不承诺任意单体与交联网络 |
| [mBuild](https://github.com/mosdef-hub/mbuild) ＋ [Foyer](https://github.com/mosdef-hub/foyer) | 层次化连接与材料构建配方；SMARTS 类型分配和既有力场应用 | 材料专属构建块、连接位点、规则覆盖及参数导出审查 | 特殊几何／表面修饰的候选；不是与 polyply 同时必装 |
| [pymatgen](https://github.com/materialsproject/pymatgen) | 晶体结构、材料对象和表面／界面相关处理 | 材料与切面配方、表面终止、坐标导出及独立力场准备 | 固相／纳米材料时再接入；不把几何生成器当力场库 |
| [MDAnalysis](https://github.com/MDAnalysis/mdanalysis) | 多引擎轨迹读取、选择与已有分析算法 | 统一输入契约、单位、周期处理、研究选择和结果封装 | 沿用现有环境，按性质增加分析器 |
| [PyMBAR timeseries](https://pymbar.readthedocs.io/en/stable/timeseries.html) | 相关性、统计低效因子及平衡起点的启发式估计 | 明确适用观察量、窗口和跨重复汇总；报告失败与限制 | 统计接入候选；自动检测不能证明跨越所有慢势垒 |
| [physical_validation](https://github.com/shirtsgroup/physical_validation) | 分子模拟物理数值质量测试 | 准备其测试要求的输入与对照，把结果接入独立质量报告 | 与模型物性验证互补，不替代力场适用性验证 |

可以借鉴的设计重点：mBuild 的可复用构建块、Foyer 的“结构与参数分离”、Interchange 的明确参数化体系交接、MDAnalysis 的独立分析接口。不是把这些项目源码搬来，也不是再建立多套运行核心。

GROMACS 还有官方 `gmxapi`。当前不建议仅为了“Python 化”把已工作的命令行适配全部改写：其安装与特定 GROMACS 构建绑定，MPI 也有对应要求。先沿用现有有界子进程和 PreparedStage 交接；出现明确收益后再单独评估。[gmxapi 使用说明](https://manual.gromacs.org/current/gmxapi/userguide/usage.html)

## 6. 原生分析能做什么，我们还缺什么

不能笼统说“分析算法都需要我们写”。GROMACS 已有不少直接可复用的方法：

| 目标 | 原生／外部方法 | 项目还要补的语义与验证 |
|---|---|---|
| 能量、温度及可用的密度／体积等记录 | `gmx energy` 读取 EDR，已有均值、漂移和分块误差估计 | 稳定识别所需量、选择时间窗、记录单位与方法；依系综解释，不把工具误差一律称为科学置信区间 |
| 组分结构与近邻 | `gmx rdf`，包含 RDF 与累积数量输出 | 原子／分子中心选择、排除、归一化及均匀／界面适用条件 |
| 扩散 | `gmx msd` | 周期连续性、分子身份、漂移处理、拟合时间窗、扩散区间和有限尺寸影响检查 |
| 聚合物尺寸 | `gmx polystat` | 主链顺序、端点和跨周期连接；环状／支化链不能不加判断地套用线性链端点规则 |
| 课题特定接触／吸附 | 现有 MDAnalysis 路线和按定义扩展的分析器 | 接触、驻留、吸附量与自由能分别定义，不能相互替代 |
| 相关性与多重复比较 | 原生工具的适用统计＋PyMBAR 等 | 共同分析规范、重复单位、有效采样、不确定性与全部失败记录 |

相关方法边界见 [energy](https://manual.gromacs.org/current/onlinehelp/gmx-energy.html)、[rdf](https://manual.gromacs.org/current/onlinehelp/gmx-rdf.html)、[msd](https://manual.gromacs.org/current/onlinehelp/gmx-msd.html)、[polystat](https://manual.gromacs.org/current/onlinehelp/gmx-polystat.html)。例如 MSD 拟合必须选到适用区间，不能因命令输出一个扩散系数就认可它。

当前项目只登记了 `hydration_contacts`、`component_contacts` 两类分析器。建议先接入通用热力学记录，再按首个研究目标添加 RDF／MSD／链尺寸中的必要项。不要为“通用平台”一次写齐所有性质。[当前分析登记表](../../src/materiasim/analysis/registry.py)

分析输入也需要扩展：现有接触分析读取 GRO、XTC 和映射；需要质量、键或更完整拓扑的方法应声明适当的输入角色，并验证当前分析依赖能否解析目标版本 TPR。不能仅因 GROMACS 能写出文件，就假定所有分析库版本都能读取。

## 7. 具体落到 MateriaSim：保留什么，补在哪里

### 7.1 沿用现在的目录职责

| 已有位置 | 配置／代码放什么 | 不应该放什么 |
|---|---|---|
| `catalog/models/` | 可复用材料模型、坐标／拓扑、小型必要资产与来源 | 生产轨迹、机器环境、研究专属运行数量 |
| `catalog/interaction_bundles/` | 精确模型组合及共享参数、适用性声明 | 无依据的“所有力场都兼容”标签 |
| `catalog/protocols/` | 有说明和适用条件的 MDP／协议资产 | GPU 编号、研究批次目录 |
| `examples/` | 单个最小可运行配置，明确工程或验证用途 | 未实现的场景却标为可运行示例 |
| `studies/` | 研究说明、显式实验、条件／种子、观察量和比较设计 | 复制的 runner、生成的长轨迹 |
| `src/materiasim/` | 共享解析、构建／引擎适配、执行、分析、研究编排 | 某个研究专用分支堆进公共 runner |
| 明确的仓库外存储 | Run、控制账本、轨迹、检查点、独立分析和备份 | 把 Git 提交当数据备份 |

这不是新的目录迁移方案。结构继续沿用；新材料先从共享模型资产与明确接入点补齐，不为每种组合创建一套顶层工程。[项目 README](../../README.md)、[研究包指南](research.md)

### 7.2 当前真实配置关系

原生 v3 配置可参考 [packed_zil_water.json](../../examples/v3/packed_zil_water.json)。它是工程示例，不能直接改一个 `purpose` 就作为正式方案。

| 现有字段 | 负责配置什么 | 当前限制／注意事项 |
|---|---|---|
| `components` | `id/model/count/role`；模型的 `resolution/provenance/files` | 未提供的历史来源不能补造；仍须符合后端资产支持范围 |
| `interaction_bundle` | 精确 `model_hashes`、参数资产、原生参数与 `validation_scope` | 不是参数生成器，也不是任意力场混搭许可 |
| `scenario` | `kind`、`boundary`、`builder.id/config` | 目前仅三个已登记场景；新场景需要实现与登记 |
| `protocol.stages` | 阶段、MDP 资产、物理声明、状态继承和目标步数 | 物理声明与 MDP 必须一致；不能绕过原生白名单 |
| `analysis_requests` | 请求方法、阶段与方法配置 | 只有两类接触分析已登记，允许空列表 |
| `execution_profile` | 工具定位、设备、线程、时间与存储预算 | 新非 smoke 用途要求 profile v3；不是无限规模开关 |
| `purpose_policy` | 参数／协议／验证证据与目标环境绑定 | 本地审核声明，不是认证签名，也不自动判断科学充分性 |

研究层仍使用 `research.json` 引用实验与重复；目前只支持有限的显式变化维度。未来链长分布、材料种类或其他研究变量如超出现有比较契约，应先扩展该契约及测试，不能把不同物理模型伪装成同一数量扫描。[当前研究校验](../../src/materiasim/research/schema.py)

### 7.3 真正需要补代码的地方

| 功能缺口 | 现有接入位置 | 应补的内容；不是重写的内容 |
|---|---|---|
| 新材料模型接入 | `catalog/`；`engines/gromacs/parameters.py`、`specification.py` | 导入经准备的模型和完整依赖，支持所需拓扑特征；不自己拟合全部力场 |
| 混合溶剂／盐配方 | `specs/composition.py`、`scenarios/`、`builders/` | 组成解析、整数化和电荷核算，明确多溶剂／离子装配；调用原生工具或 Packmol |
| 聚合物／表面构建 | `builders/registry.py`、`scenarios/planning.py` 及对应适配器 | 调用所选工具，保存配方、种子、映射并返回实际 BuildResult；不复制研究 worker |
| 新边界和协议特征 | `specs/protocol.py`、`engines/gromacs/mdp.py`、原生编译与校验 | 逐项开放需要的参数／参考资产／输出角色并测试；不是取消所有校验 |
| 新分析与科学统计 | `analysis/registry.py`、分析实现及 `research/` | 包装成熟方法、核对输入，记录单位和不确定性；不重新实现已有 RDF／MSD 算法 |
| 正式规模和服务器执行 | `specs/execution.py`、`runtime/`、`research/schema.py` | 调整经过验证的资源上限、存储策略和必要的作业调度；不写 CUDA 力计算 |

这里存在一个容易忽略的实际阻塞：当前 `parameters.py` 接受的是显式 GAFF 形式的受限拓扑，分子资产中的宏／include 和多种其他拓扑段会被拒绝。因此，**第三方工具导出了合法 GROMACS 文件，也不保证当前 MateriaSim 能接收**。应该建设有测试的模型导入／原生解析交接路线，保留有效参数核查，不能删检查强行拼文件。[当前参数装配](../../src/materiasim/engines/gromacs/parameters.py)

构建输出继续交给 [BuildResult 核查](../../src/materiasim/builders/contracts.py)，阶段编译继续交给 [PreparedStage 核查](../../src/materiasim/engines/prepared.py)。新能力应复用现有生命周期和证据契约，而不是再创造另一套“成功”标准。

### 7.4 当前限制与上游能力必须分开标注

| MateriaSim 当前约束 | 影响 |
|---|---|
| 总原子 ≤20,000；Packmol 路线显式非溶剂原子 ≤2,000 且要求电中性 | 大链和大颗粒可能在构建前被拒绝，不能只调 GPU 参数 |
| 1–8 种显式组分，每种 1–100 个；水走独立填充路线 | 不是任意配方／浓度／多溶剂支持 |
| 正交盒、三维周期、边长 3–6 nm | 真空、通用薄层和非正交晶胞需要对应接入 |
| `tip3p_fill` 或 `none`；无水路线目前要求固定体积 | 不支持任意水模型／混合溶剂，也不等于熔体或固体制备 |
| 一次初始 EM＋动力学，共 2–8 个线性阶段；`steep/md`、dt≤0.002 ps | 不支持任意阶段图、自动交联过程或粗粒化协议 |
| MDP 白名单未含 `pull`、`annealing`、`ewald-geometry` 等 | 原生 GROMACS 有相关机制，但不能直接塞进当前协议 |
| 非 smoke 采样要求关闭全精度坐标／速度／力输出流 | 依赖这些输出的分析需先扩展输出与容量契约 |
| Research 最多 16 个任务、串行、总预算 ≤1800 秒／1 GiB | 不能直接开展长时间的大批研究；单实验 profile v3 的较长预算不解除此约束 |
| 单 CUDA GPU 非键／可选 PME 是候选路径，bonded/update 仍 CPU | 未进行 Linux/GPU 硬件验收，不能宣称支持所有 GPU 或多卡 |

限制依据：[原生适用性](../../src/materiasim/engines/gromacs/specification.py)、[装配规则](../../src/materiasim/scenarios/packed.py)、[MDP 处理](../../src/materiasim/engines/gromacs/mdp.py)、[阶段契约](../../src/materiasim/specs/protocol.py)、[执行配置](../../src/materiasim/specs/execution.py)、[研究预算](../../src/materiasim/research/schema.py)。

这些是当前项目的可控子集，不是 GROMACS 的总体能力边界。应按所需场景扩展并验收，不应一次性删除上限或把未知特征当作默认支持。

## 8. 环境与执行应怎样配置

### 8.1 最小环境和按需环境

| 环境用途 | 建议配置 | 本轮状态 |
|---|---|---|
| macOS 小量验证 | 独立 Python 环境＋MateriaSim＋原生 GROMACS；自动装填时使用 Packmol；需要分析时使用现有分析依赖 | 复用已有路线，不安装或升级 |
| 新模型准备 | 仅安装该参数化／构建路线所需工具；依赖冲突时与运行环境分离，以有身份的文件资产交接 | 待选具体路线后授权与验收 |
| Linux CPU/GPU | 在服务器独立建立环境，固定 GROMACS 构建、驱动／设备信息和工具版本 | 待目标硬件实际验收；不复制 Mac 虚拟环境 |
| 集群调度 | 明确单任务／批次资源、退出宽限、检查点和作业身份；需要时接入 Slurm 等实际环境 | 当前无完整远程调度能力，不是本轮实施内容 |

当前包的分析依赖锁定为 MDAnalysis 2.7.0、NumPy 1.26.4，核心无第三方运行依赖；新建模工具不能未经评估塞进同一环境。[实际依赖声明](../../pyproject.toml)

### 8.2 当前可用的只读检查入口

在仓库根、激活已安装本项目的对应 Python 环境后：

```sh
materiasim doctor --packmol packmol
materiasim doctor --devices
materiasim capabilities
materiasim tools
materiasim validate examples/v3/packed_zil_water.json
materiasim research validate studies/mixed_builders_smoke/research.json
materiasim research plan studies/mixed_builders_smoke/research.json
```

这些命令不启动模拟；研究 `plan` 未传输出选项时只预览。命令来自当前 [CLI](../../src/materiasim/cli.py) 和[研究指南](research.md)。缺工具应报告，不在 doctor 中自动安装。

执行仍走现有 `build → run/resume → analyze → report`，具体参数与读写边界见[单实验指南](simulation.md)。本指南不提供一个带占位化学参数的“生产命令”，避免把未准备好的模型当作可执行研究。

### 8.3 上服务器前的必要演练

1. 同一个小体系在目标环境完成构建、短动力学、分析和检查点恢复。
2. 从原生日志确认实际 CPU/GPU 工作分配，不以设备可见或退出码零替代。
3. 用代表性规模测计算速度、内存和磁盘增长，连同轨迹副本成本估算预算。
4. 演练作业超时／中断、备份与恢复；保留 Run、控制账本、分析及研究计划／批次证据。

GROMACS 已提供原生检查点与续跑，但项目仍需管理任务身份和输出；检查点也不能替代异地备份。跨硬件不要求轨迹逐位相同，应在明确条件下比较统计性质。[长模拟、续跑和可复现性](https://manual.gromacs.org/current/user-guide/managing-simulations.html)

当前 MateriaSim 不提供活动 Run 的跨平台迁移服务；变更引擎／执行身份时不能绕过恢复检查。单 Run 的只读归档也不自动包含整个 Research 批次，完整研究仍需保留计划、账本和比较产物。[项目恢复与归档边界](simulation.md)

## 9. 验证应如何分层，不把“跑通”当成“科学成立”

| 层次 | 要回答的问题 | 典型证据 |
|---|---|---|
| 输入与编译 | 是否模拟了声明的模型和组成？ | 参数完整、原子顺序／连接／电荷／数量一致、实际 TPR 与展开参数 |
| 数值与工程 | 是否按要求稳定执行并正确保存？ | 最小化结果、原生日志、实际步数、约束异常检查、检查点与文件完整性 |
| 物理数值质量 | 所选数值设置是否按预期工作？ | 适用的守恒／系综等检验；依据模型与协议选择，不能把 NVT 的总能漂移直接当 NVE 标准 |
| 采样质量 | 目标观察量是否有足够信息？ | 多时间窗、慢变量、相关性、重复初态、有效样本和不确定性 |
| 模型适用性 | 是否能合理解释目标材料与性质？ | 与实验／可信基准比较，必要的敏感性与尺寸检查，明确适用范围 |

可以借用 physical_validation 等工具做特定物理数值测试，但它不是任意材料的科学认可器。[physical_validation](https://github.com/shirtsgroup/physical_validation)

同样，PyMBAR 的平衡检测是针对输入时间序列的启发式估计；某个量平稳、换了几个速度种子，不能证明体系探索了所有相关构象。[timeseries 方法说明](https://pymbar.readthedocs.io/en/stable/timeseries.html)

项目应把这些层次分别报告为通过、失败或未评估，保留全部声明的重复。没有预先确定的材料和观察量，不能承诺固定的 ns 数就是充分模拟时间，也不能估计正式计算成本。

## 10. 在当前阶段，推荐的落地顺序

以下是本指南的优先级建议，不是已经执行的新开发计划。

1. **先把现有运行核心用好**：保留状态、冻结、续跑和独立分析机制；不再泛化搬目录。
2. **补一个有用的正式前置闭环**：模型导入／审查、组成检查、热力学记录提取、目标性质与采样报告。不要自动升级现有 `engineering_only` 资产。
3. **优先扩展参数化小分子与混合溶剂装配**：复用现有 Packmol 路线和必要原生工具，完成组成与拓扑交接测试。
4. **接一个具体聚合物路线**：从适用库／已参数化模型出发，补链身份、构建和链分析；不承诺先覆盖所有聚合物。
5. **有材料目标后再接固相／纳米界面**：先选模型和边界，再决定复用哪种结构工具、扩哪些原生特征；必要时评估其他引擎。
6. **按实际规模完善 Linux/GPU 与长任务**：资源约束、调度、轨迹存储和恢复验收跟随代表性任务，而不是仅改一个 GPU 标志。

每一项新能力的最低交付应包括：一个真实配置、完整小型输入、输入错误拒绝测试、原生短程贯通、所需分析结果与明确限制。工程例可以先建好，但正式模型批准必须有独立科学证据。

最终边界可以概括为：**成熟软件负责算法和原生计算；MateriaSim 负责让正确的模型、组成、场景、协议和观察量以可核查的方式连接起来。** 不同场景共享执行核心，但不共享一套未经判断的物理流程。
