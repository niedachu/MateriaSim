# MateriaSim 插件化研究 Harness：方案简介与实施边界

## 1. 结论与目标

建议采用：**稳定的科学执行核心＋显式注册的能力插件＋结构化研究包＋持久化无人值守控制层＋可选外部 agent 接入。**

参考 DeepSeek Harness 的能力分离、配置组合和事件留痕，不照搬其整个运行时，不把 Python 模拟核心改写成 TypeScript，也不让可替换插件绕过科学校验。先用已有工程体系贯通真实闭环，再逐个增加材料和场景。

本轮授权仅为调研和方案文档。所有新增目录、类型、接口、状态和文件名均为**拟议设计，不是已经存在的命令/API**。本文不替代材料覆盖、乙醇验证或 Linux/GPU 验收计划。

二次审查补充见 **§13**：它细化前文要求并约束 H0—H6 的验收，不另立第二份实施计划。尤其修正“暂停／取消／人工审查”“宿主离线／模型离线”“插件注册／真正可组合”容易混淆的边界。

## 2. 现状：不是每个场景都有一个研究包

本地基线为提交 `d1a284b`；2026-09-17 只读核查如下：

| 层次／内容 | 实际状态 | 依据 |

| 构建能力 | 预建输入、GROMACS＋Packmol 装填两条实现 | [构建注册](../../src/materiasim/builders/registry.py) |
| ZIL 数量研究包 | 已有研究定义、实验、种子、预算和工程判据 | [zil_count_smoke](../../studies/zil_count_smoke/README.md) |
| 双构建场景研究包 | 已有预建／装填 CAT/ANI 两条件、四任务、双接触分析 | [mixed_builders_smoke](../../studies/mixed_builders_smoke/README.md) |
| 乙醇—水 | 只有来源获取和候选审查；没有可执行研究定义 | [准备包](../../studies/ethanol_water_benchmark/README.md) |
| 聚合物、大分子、纳米材料、固相／界面 | 未形成受支持的可执行场景和研究包，不是单纯漏填配置 | [能力矩阵](../knowledge/platform/capabilities.md) |
| agent 操作入口 | 已有命令发现、JSON 响应、结构化错误、用途门禁和操作账本 | [CLI](../../src/materiasim/cli.py)、[控制层](../../src/materiasim/runtime/control.py) |
| 无人值守研究决策 | 当前为固定计划的串行执行，首个未解决失败即停；无完整的 agent 决策闭环 | [批次执行](../../src/materiasim/research/batch.py) |

当前研究定义 v2、冻结计划 v3、Experiment/Run v3 是不同契约，不统一改版本号。现有研究限制为至少两个条件、最多 16 个任务、串行、批次 1800 秒／1 GiB；单实验不应为满足研究定义而被伪造为两个条件。[研究 schema](../../src/materiasim/research/schema.py)

必须区分：

- **材料资产**回答“使用哪个分子／力场模型”：坐标、拓扑、来源与适用范围。
- **场景**回答“怎样装配和施加边界”：水溶液、无水周期盒，以及未来的界面等。
- **能力插件**回答“谁实现构建、执行、分析等操作”：真正有代码和输入输出契约。
- **研究包**回答“研究什么、比较哪些条件、观察什么”：组合资产、场景、协议和分析。
- **Campaign**回答“此次无人值守任务授权做到哪里”：选择哪些任务、如何决策、何时停止。

因此，不按“小分子插件／聚合物插件／纳米插件”建立三个全包式子系统。一个研究包可以比较多个场景，同一个场景可以服务多个研究包；新增一种已有格式的小分子通常首先新增资产，不必新增 Python 插件。

## 3. DeepSeek Harness 调研与取舍

### 3.1 已核读的官方设计

DeepSeek Harness 使用 Cordis 组织插件，模型、工具、会话与循环等能力可组合；profile/bundle 负责部署组合，持久会话事件与即时运行事件有不同职责。这里借鉴职责分离，不复刻整个通用 agent 平台。[官方架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)

其开发指南区分“接口定义、实现提供方、工具消费方”，并明确不要求所有角色立即拆成独立包；只有独立演进需要时才拆。这适合 MateriaSim 先保留单 Python 包、按职责建立边界。[能力角色指南](https://deepseek-harness.github.io/deepseek-harness/develop/practice/)

插件通过显式服务依赖组合；工具入口分别定义参数、规范结果与面向模型的展示。我们的 agent 工具也应展示摘要、返回可核查证据引用，而不是把屏幕文字当真实运行状态。[服务与依赖](https://deepseek-harness.github.io/deepseek-harness/develop/framework/service)、[工具开发](https://deepseek-harness.github.io/deepseek-harness/develop/basic/tool)

官方仍标为开发者预览并提示破坏性变更；安全说明指出它尚未经安全审计，不能作为不可信工作负载的唯一隔离措施。因此不把它作为 MateriaSim 核心强依赖，也不因配置了插件权限就声称安全隔离。[官方仓库](https://github.com/deepseek-ai/deepseek-harness)、[安全说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/SAFETY.md)

阅读范围：官方架构、能力分层、服务依赖、工具示例、README 和安全说明；访问日期 2026-09-17。引用为当日在线文档／master 页面，未固定上游提交、未安装或做运行验证，亦非全仓库源码审计。正式接入前必须再锁定发布版本／提交、许可和接口测试；不依据社区宣传判断安全或科学能力。

### 3.2 借鉴与不照搬

| 设计 | MateriaSim 的选择 |
|---|---|
| 能力可组合、实现可替换 | 采用显式契约和白名单注册，先将现有实现包装为内置能力 |
| profile／bundle | 组合插件与工具入口，但不覆盖实验物理参数、预算或用途批准 |
| 事件留痕 | 新增 Campaign 决策事件；引用现有 Run、分析与预算账本，不替代它们 |
| 工具与服务分离 | CLI、将来的 DeepSeek 插件都调用同一个领域服务 |
| 动态加载／热替换 | 活动模拟禁止更换执行插件、模型或协议；新版本进入新任务 |
| 自修改、任意 shell、在线装插件 | 无人值守科学执行不开放；研发与运行分开授权 |
| 所有能力都可替换 | 不采用：最低权限、预算、输入完整性和用途门禁不能被插件关闭 |

另参考本机 feature engineering 的 `agent_tuning/dc_phase/unattended.py` 与 `permissions.py`：借鉴固定父任务、持久状态、证据审查节点和参数权限；不复制量化目标函数、Long/Short 结构、环境或依赖。本次核查的是该无人值守路径，不声称覆盖其全部 Autopilot 子系统。

## 4. 目标结构：领域核心与 agent 宿主解耦

```text
用户授权／研究问题
        │
        ▼
研究包 studies：资产引用＋条件＋协议＋观察量＋验收规则
        │
        ▼
Campaign 控制层：任务身份、权限、状态、预算汇总、决策证据
        │                         ▲
        │                  agent 提议／规则决策
        │                         │
        │              外部宿主适配器（DeepSeek 等，可选）
        ▼
现有 research / workflows：冻结、构建、执行、恢复、分析
        │
        ▼
已注册能力：scenario / builder / engine / analyzer
        │
        ▼
GROMACS / Packmol       →       Run、检查点、AnalysisRun
```

核心依赖方向：宿主适配器依赖领域工具契约；Campaign 依赖现有工作流；实现依赖契约。模拟核心不导入 DeepSeek/LLM SDK，研究包不复制 runner。

两种“插件”分开命名：

1. **MateriaSim 能力插件**：本项目可审计的构建／引擎／分析等扩展。
2. **DeepSeek 宿主插件**：把 MateriaSim 工具提供给 DeepSeek 的薄适配器，可独立移除。

第一版不做插件市场、不自动 `pip/npm install`、不做通用事件总线和多智能体系统。先完成本地 CPU 串行闭环；Linux/GPU 和调度器是后续独立验收，不混入首版完成声明。

## 5. 能力插件：复用现有接口，补足注册和身份

现有 [EngineAdapter](../../src/materiasim/engines/contracts.py)、[构建交接](../../src/materiasim/builders/contracts.py)、[分析契约](../../src/materiasim/analysis/contracts.py)已提供基础，不另造一套平行接口。

| 扩展点 | 首版范围 | 后续按具体需求扩展 |
|---|---|---|
| 场景与构建 | 包装现有三个场景、两条构建路线 | 聚合物、表面等专属模型与构建工具适配 |
| 数值引擎 | 现有 GROMACS 适配器 | 有真实需求才增加其他引擎 |
| 分析 | 现有两类接触与整盒密度／体积 | RDF、MSD、构象、界面等逐项接入 |
| 执行后端 | 复用本地监督器，不把 CPU/GPU 各做一套研究插件 | 服务器调度器适配与设备验收 |
| 决策提供方 | 确定性规则与外部结构化 agent 决策 | 特定宿主连接；不让模型直接写控制账本 |
| 知识／通知 | 知识引用作为证据，事件驱动通知 | 有需要再做检索或 UI 插件，不先建向量数据库 |

拟议每个能力描述至少记录：唯一 ID、种类、契约版本、实现版本／哈希、依赖与输入输出格式、配置 schema、支持的用途／组合、读写与资源需求、验收证据引用。`implemented`、`environment_checked`、`engineering_validated`、`scientific_applicability` 分开表达，插件自报标签不是批准。

插件注册分两步：先读取描述和校验依赖、重复 ID、契约兼容及授权，再激活已审查实现；不扫描目录自动 import 未知代码。首版仅内置显式白名单，不引入动态 Python entry points。将来确需外部分发再增加安装、签名／信任和进程隔离设计。

同进程 Python 插件拥有宿主权限，注册表和 JSON schema **不是沙箱**。不可信扩展不得进入首版。活动 Campaign 固定有效插件集合；恢复时核验实现身份和原生工具身份，版本不匹配安全停止。现有实现闭包检查必须覆盖新增调用路径；外部插件上线前必须补其闭包哈希，不能只记录版本字符串。[现有身份实现](../../src/materiasim/runtime/identity.py)

## 6. 研究包：统一结构，不把每个包变成程序

保留当前 `studies/<id>/README.md`、`research.json`、`experiments/`，不大搬目录。建议新增以下**按需文件**，不为未支持体系创建空包：

```text
studies/<study_id>/
  README.md              已有：目标、支持范围、来源和限制
  research.json          已有：显式条件、重复、观察量和研究判据
  experiments/           已有：完整实验配置；模型／协议优先引用 catalog
  automation.json        拟新增：所需能力、允许动作、审查节点与停止策略
```

`automation.json` 是研究包声明的需求和限制，不是用户授权书；运行时有效权限取“平台硬约束 ∩ 用户授权 ∩ 研究包限制”，包不能给自己扩权。预算数值仍由现有实验／研究定义拥有；Campaign 只增加跨批次总额，不复制一套逐 Run 配置。

先用单独的自动化侧车契约组合现有研究定义，不为了 harness 无条件升级所有 schema。准备中的乙醇目录没有 `research.json`，发现服务应返回 `preparation_only` 与缺口，不生成伪造配置使其成为“可执行”。单实验则直接引用已有 Experiment，不受“至少两个研究条件”限制。

研究包预检输出建议包含：身份与资产哈希、所需／缺失能力、环境检查、可执行范围、用途证据、预计任务数、冻结预算、可执行动作和人工审查原因。无法通过预检时，不创建 MD Run、不下载参数、不自行安装工具。

## 7. 无人值守闭环：决策可以替换，执行裁决不能绕过

### 7.1 Campaign 与既有批次的关系

Campaign 是包在普通实验或研究批次外面的受控任务，不取代 Batch/Run。首版使用现有批次粒度；若以后需要每个条件或阶段间决策，再给现有批次增加受测的单步推进接口，不复制 `advance_task`、不直接从外部调用私有内部函数绕过锁。

建议在明确的仓库外 Campaign 根保存：冻结 manifest、追加事件、状态投影、agent 决策、证据引用和执行操作关联。状态投影可从事件重建；事实依据仍分别归属 Run、AnalysisRun、批次和操作账本。事件记录公开的决策理由摘要、参数差异和证据引用，不要求隐藏推理链，也不保存 API 密钥。

拟议控制流程：

```text
created → preflight → ready → executing → reviewing
                                      ↖    │
                           已授权下一步 ────┘
reviewing → completed / needs_human_review / budget_exhausted / failed
```

`waiting_for_agent` 与 `needs_human_review` 是停派新工作的等待状态，不是完成态；人工解决问题后须经新的有效授权／决策才能继续。取消须先进入 `cancelling` 并核实已登记 worker 停止及证据保存，才记为 `cancelled`；无法确认则进入人工审查。暂停则是可恢复的独立状态，不复用取消。完成仅表示约定的工程／研究工作已执行，科学质量仍可为 `not_assessed`；具体规则见 §13.4。

### 7.2 首版动作及权限

| 动作 | 首版规则 |
|---|---|
| 读取状态／证据、验证候选 | 允许受限路径内只读访问；不以文件存在替代完整性核查 |
| 执行下一项 | 只能选已批准、已冻结的实验／计划；提交前再次核验身份 |
| 恢复中断 | 必须有用户预授的恢复权限、有效检查点、原身份与剩余预算；沿用核心允许的状态 |
| 执行分析 | 只用已声明方法、输入和输出；失败后不无限重分析 |
| 停止／请求审查 | 可主动停止；数值异常或缺参数必须明确报错 |
| 改组成、重复数、采样目标 | 首版不自主生成；后续须在预授范围内派生新计划／新 Run，保留父子关系 |
| 修改力场、电荷、水模型、约束、步长、源码 | 不属于无人值守常规权限；需要专门设计和批准 |
| 改预算、批准 production、在线装插件、下载资料 | 不允许包／agent 自行完成，须另行授权 |

判据不可在看到结果后由 agent 放宽；科学统计方法和比较口径也不能为追求“通过”而修改。失败、重复和负结果全部保存，既有短程工程结果不晋升为材料验证证据。

### 7.3 决策、幂等与预算

拟议决策契约包含：Campaign ID、预期事件序号、request ID、动作、目标计划／Run 哈希、证据哈希、理由摘要、有效期。请求和结果都须校验；旧决策、伪造证据、重复 request ID 不得触发新计算。相同 ID 配不同内容直接拒绝。

调用前预留资源并保存意图；调用后核实结果再结算。崩溃发生在提交与回执之间时，先按已登记操作身份核对，不能宣称跨进程天然“恰好一次”，更不能盲目重试。Campaign 额外管理跨批次总预算及模型调用次数／费用上限（若接在线模型）；复用底层账本核算，避免双重计费，也禁止靠新建批次无限重置总预算。

### 7.4 三种运行等级，分别验收

1. **规则无人值守**：不需要在线 LLM，执行已批准计划，按确定性工程规则完成／停止。这是首版真实闭环。
2. **agent 驱动无人值守**：agent 在 `reviewing` 读取证据并提议动作；宿主失联时等待，有限重试仅用于已分类的通信错误，不重复模拟。
3. **自适应科研**：按预注册科学策略追加采样／重复或新条件；须先补相应统计与派生协议能力，不属于首版。

常驻监督器应与交互会话解耦，使用持久任务 ID 和心跳管理本地 worker；不是让 agent 的一次 shell 调用一直占住等待。父监督器退出后需核对存活 worker，SIGKILL／磁盘满／残留锁等不确定情形安全停止。首版应测 Mac 会话退出与恢复，不能凭后台启动就宣称服务器长时可靠。

## 8. 可选 DeepSeek 宿主插件

在领域契约稳定后单独提供薄适配器：DeepSeek 工具 → 有界 JSON 请求 → MateriaSim 服务入口 → 规范 JSON 响应／证据引用。优先受控本地子进程／stdio，不开放公共监听端口；真正的后台任务归 Campaign supervisor 管理，而不是绑在一次模型调用的子进程生命周期上。

拟议工具只提供能力查询、预检、创建／推进任务、状态、证据读取、提交决策和取消。禁止传入任意 shell 字符串、任意 Python import 路径或账本写入内容。适配器只映射参数与结果，不持有另一套模型参数、预算或科学判据。插件卸载断开 agent 连接，不直接删除或强杀 MD；按冻结的断连策略完成当前有界操作后等待。

DeepSeek 的工具 schema 负责第一层格式检查；MateriaSim 在服务边界仍需重新执行权限、路径、身份与科学校验。宿主端如同时提供 unrestricted shell／文件写权限，仍可能绕过领域工具；因此正式部署须以独立账户／受限文件系统和凭据隔离约束宿主，不能只靠提示词。

不要求用户先安装 DeepSeek；不用它仍可通过现有 CLI 和后续 Campaign CLI 运行。本文只确定适配方向，不承诺当前 DeepSeek API 兼容性或后台运行性能。

## 13. 二次审查补充：实施前必须闭合的边界

本节为设计要求，不是新能力声明。审查发现前文的总体分层可保留，但仅有“插件＋状态机”的描述尚不足以安全实施。以下要求分别并入 §10 原有批次，不新增空泛的平台开发主线。

### 13.1 最小契约与唯一事实归属（H0）

拟议契约字段应在 H0 固化并提供合法／非法夹具，避免实现时各层各自定义一套 JSON。下表是字段组，不是可直接提交的现成 schema。

| 契约 | 最小字段组与职责 |
|---|---|
| AutomationSpec | 自身版本、研究／实验引用、所需能力、审查边界、允许动作、失败与断连策略；未知字段拒绝 |
| CampaignManifest | Campaign 身份、冻结计划及资产引用、解析后的插件组合哈希、用户授权引用、范围／预算、创建环境；创建后不覆盖 |
| Authorization | 授权主体、作用范围、允许动作、可读写根、资源上限、有效期、撤销状态；独立于 agent 决策 |
| OperationIntent | 操作 ID、目标身份、幂等键、期望状态版本、预留额度、worker 所有权；提交前持久化 |
| Decision | 决策来源、动作、目标、所见证据／事件序号、理由摘要；只表达提议 |
| EvidenceSummary | 原始证据 ID／哈希、方法与单位、窗口、失败／缺失、工程／科学状态；摘要不能替代源文件 |

父 Campaign 只拥有调度事实和汇总；MD 状态归 Run，分析归 AnalysisRun，底层开销归既有操作账本。发现多处状态冲突时进入核对，不以最后写入者获胜。不同契约独立版本化；不支持的新版本拒绝，历史只读解析不得改写原证据。

### 13.2 插件必须真正参与执行，而不只出现在目录里（H1）

当前 [原生适配](../../src/materiasim/engines/gromacs/specification.py)仍绑定场景／构建器、TIP3P、正交三维周期边界、粒子与盒子范围；[状态核验](../../src/materiasim/runtime/state.py)也含 GROMACS 特定假设。它们是已实现子集的边界，不应删除检查来实现“通用插件”。

必须使能力发现、配置校验、构建和子进程执行消费同一份解析结果：

1. H1 的内置白名单由一个权威注册源产生，避免 `capabilities` 宣称可用而 worker 仍使用另一套全局字典。
2. 组合只允许显式能力 ID，拒绝未知提供方、重复 ID、依赖环与冲突；可选依赖缺失须让相关功能不可用，而不是静默换实现。
3. 冻结“解析后组合”及各能力配置哈希，传递给 worker；子进程重新核验后执行。配置层不允许随意覆盖 profile 中的物理、预算或批准字段；拒绝不明确的合并优先级。
4. H1 先包装现有真实实现，只拆为此次组合所必需的绑定；保留 GROMACS 专属约束。新增材料／第二引擎时，再按真实需求拆除对应耦合并单独验收。
5. 插件兼容不止是 API 版本相同：须核验“材料模型＋相互作用包＋场景边界＋协议＋输出格式＋分析方法”的组合。能分别运行的插件不代表能科学兼容地组合。
6. 增加仓库内与隔离安装态的解析一致性测试，不依赖开发目录、当前 shell 路径或原案例绝对路径。动态 import 不在现有 AST 实现闭包保证内；未受测前不开放动态入口。

### 13.3 授权必须能识别、撤销，并阻断旧请求（H0/H2/H4）

首版定位为本机单用户控制，不声称密码学身份认证或多租户安全。用户通过明确的管理入口授予 Campaign 权限；agent 接口只提交决策，不能创建、续期或扩大自身授权。权限文件若与 agent 共用可写目录，单靠哈希无法防止篡改；非对抗性的本地可追溯声明与真正隔离部署须分别报告。

新增撤销规则：每次启动／恢复操作前重新核验授权有效期与撤销状态；用户取消或撤销后阻止排队中的旧决策。已经运行的操作按预先批准的停止策略协作退出并保全证据，不保证信号瞬时生效。扩权只能由用户创建新授权修订，追加事件并使旧决策失效，不直接编辑冻结 manifest。

DeepSeek 的权限预设只是对沙箱与审批选项的组合，实际强制执行仍由各自机制负责；MateriaSim 的授权边界也不能由宿主下拉选项代替。[官方权限预设文档](https://deepseek-harness.github.io/deepseek-harness/reference/subsystems/permission-presets)（2026-09-17 核读）

### 13.4 暂停、取消、终止与断连分开处理（H2）

- `pause_requested → paused`：暂停新投递，等待当前操作安全结束／可核验中断；在原授权、身份、预算和核心状态允许时恢复。
- `cancelling → cancelled`：用户明确终止此 Campaign；未核实进程结束前不显示已取消。以后需要新工作建立新 Campaign，不把终态原地重开。
- `needs_human_review`：等待解决证据或权限问题，附机器可读原因和需要的用户动作；不能用通用“继续”按钮绕过损坏证据或核心恢复限制。
- `budget_exhausted`、`failed`、`completed` 为终态；`completed` 不等于所有科学判据通过。规则失败要明确保留为失败结论，不包装成成功。
- agent 会话断开不是取消 MD；规则模式可按已授权策略继续，agent 模式到下一决策边界等待。通知失败不改变运行事实，不触发 MD 重试。

首版支持同机 POSIX 本地文件系统，单个有效 supervisor 管理一个 Campaign；不宣称 NFS 分布式锁或多机自动接管。进程登记包含宿主／启动实例及随机所有权标识，不能只依赖可能复用的 PID；未确认所有权不得杀进程。重启接管要重新取得锁并核对 worker、事件和底层账本，不因心跳过期就删锁、清状态或重启任务。

### 13.5 恢复事务与停止时限：补全故障窗口（H2）

追加事件需序号、前序哈希、请求哈希与有限长度校验；持久提交后才响应成功。投递意图、预算预留和可重放的状态变更归同一条持久提交记录；状态投影在该记录之后更新。只有完整提交的事件驱动恢复，不把半行 JSONL 当完成，也不截掉无法确认来源的尾部后继续。落盘策略须说明刷新／同步及文件系统假设；哈希链不是防恶意篡改的认证。

| 崩溃窗口 | 必须行为 |
|---|---|
| 意图尚未持久化 | 不得已启动外部计算；重复请求仍按请求身份核对 |
| 意图／预留已保存，启动回执未保存 | 先核对操作登记与 worker；无法确认未启动时进入人工审查，不盲目重投 |
| worker 已完成，Campaign 未结算 | 从有效的底层结果对账，一次结算，不重做模拟／分析 |
| 结果已结算，客户端未收到响应 | 同一幂等键返回既有结果；相同键不同请求拒绝 |
| 事件写到一半／存储失败 | 保留尾部和原始日志、停止投递；不能因缺少完成事件判定操作未执行 |

GROMACS 的 `-cpi` 在找不到检查点时可能转为从头运行，因此 harness 不能仅靠传参保证恢复；必须沿用核心的检查点存在性、身份与步数核查。`-maxh` 的停止发生在相应邻居搜索步骤，不是严格墙钟硬截止。[GROMACS 2026.3 mdrun 文档](https://manual.gromacs.org/documentation/2026.3/onlinehelp/gmx-mdrun.html)（2026-09-17 核读 current 对应版本）

明确停止链：Campaign 停派任务 → 既有监督器发协作停止 → 原生程序保存状态 → worker 封存 → 父层核实。宽限必须覆盖内层宽限和收尾；超过硬边界才按已确认所有权强制回收。强杀后只能说“进程停止”，不能保证存在可恢复检查点。首版不自动回退到 `state_prev.cpt`，不换种子／从头算来假装恢复成功。

### 13.6 预算之外，还要定义容量和等待成本（H2/H6）

现有本地监督主要覆盖时间、线程和磁盘，并非 RAM／VRAM 硬隔离。H2 限定既有小体系；内存风险以规模门禁和异常停止处理，不能声称已有硬内存配额。H6 使用实际调度器／操作系统资源限制后再声明相应保障。

Campaign 明确区分执行耗时、总截止时间、agent 等待时限与模型调用成本；等待不算模拟 CPU 用时，但仍消耗任务期限和磁盘占用。首版串行下以操作 ID 汇总底层实际费用，父层预留不与子层实耗重复相加；未知开销保守保留预留，不删除记录释放额度。外部模型价格／用量不确定时只保证调用／token 硬上限，不能伪造精确费用。

启动前核对检查点、轨迹、分析、日志和封存副本的容量需求及收尾余量；完整存储约束覆盖 Campaign 事件与 agent 日志，不能只计算 MD 目录。摘要读取和响应设大小上限；不通过丢弃失败证据或更改已冻结输出频率解决超额。到阈值安全停止，不隐式扩容或清理历史。

### 13.7 知识、日志与外部模型的数据边界（H3/H4）

文献、研究包说明、插件描述、错误日志和通知内容都视为数据，不能因其中出现指令而扩大权限。即使知识条目写“可以继续”，执行仍由冻结规则与实际证据裁决。

外部 agent 默认只读取脱敏的结构化摘要与获准证据片段，不自动发送整条轨迹、私有分子结构、项目源码或原始实验数据。需要更多数据必须有相应读／外发授权；保留发送对象、来源哈希与访问记录。环境变量不能全量写日志；凭据只由模型连接器持有，不传给 MD worker。

当前 [进程组启动](../../src/materiasim/runtime/family.py)及 [GROMACS 环境构造](../../src/materiasim/engines/gromacs/command.py)会继承环境。实施时应在明确授权范围内设计并测试宿主到 worker 的环境白名单，保留必需路径与原生库设置；不能只在文档中宣称凭据已经隔离。若环境改变影响执行身份，记录新身份并按既有恢复规则处理。

“规则模式不需要 LLM”“不依赖交互会话”“完全断网运行”是三种不同承诺。H2 仅实现前两者的适用范围；需完全离线时，模型和资产必须预先齐备，缺少即拒绝，不后台联网。

### 13.8 科学门禁与错误分类必须可执行（H0/H2/H3）

将错误分类为配置／能力缺失、权限、完整性、资源、可核验中断、数值失败、分析失败和未知错误。分类由代码和原生证据决定，不靠 LLM 根据 stderr 文风猜测；未知默认不重试。仅已确认的通信错误可有限重试，且不能造成新的计算提交。

门禁绑定具体能力版本、研究用途和目标量；当前未封装的自动平衡、有效样本数及科学置信区间，不能从稳定密度曲线或零退出码推导为通过。H2 保留工程门禁；科学门禁待相应方法有实现和适用性证据再开放。采样不足时可给建议，但首版不擅自追加模拟。

追加重复／延长采样进入 H6 时，必须预先声明停止规则、最大追加预算及比较策略，防止反复试到“结果好看”为止。改变力场或物理协议与增加同协议采样分开记录；失败和负结果保留。跨 GPU／CPU 的验收目标也须区分运行完整性、数值统计一致性与逐位一致，不能一概要求轨迹相同。

### 13.9 Campaign 证据闭包与只读审计（H2）

当前 [archive 实现](../../src/materiasim/workflows/archive.py)只导出完成态单 Run 及其登记证据，不包含完整研究／Campaign，也不接受失败 Run。不能把它直接当作新 harness 的备份方案。

H2 至少提供终态 Campaign 的证据清单及闭包核查：包含授权修订、插件身份、冻结计划、全部成功／失败／未启动任务、底层控制账本、分析、决策和最终报告。证据缺失必须显式列出，不能导出“完整成功”标志。首版提供同机只读审计和保留说明，不承诺活动迁移或跨平台恢复；完整便携 Campaign 导出作为独立增量，不能借单 Run archive 冒充已支持。

报告需列明本次实现了哪些能力、实际运行范围、失败原因、未完成工作和科学质量；不自动删除中间文件、不提交或推送运行证据。测试本身也只能清理明确属于测试的目录，不触碰用户 Run。

### 13.10 故障注入与阶段交付定义（H1—H4）

除 §11 外，增加以下必须检查的验收项；测试夹具只证明程序行为，不证明材料科学有效性。

| 批次 | 最小新增验收 |
|---|---|
| H1 | 父／子进程选择同一实现；配置哈希变化拒绝恢复；禁用能力后发现与执行均拒绝；循环依赖和安装态路径测试 |
| H2 | 一个普通实验及两个现有研究包路径；同一批次重复提交；取消与完成竞态；暂停／恢复；授权撤销后旧决策被拒绝 |
| H2 | §13.5 每个持久化窗口故障注入；断电式未收尾状态、磁盘写失败、重复 supervisor、PID 复用不误杀；检查点缺失不从头启动 |
| H2 | Campaign 总额不能靠换批次重置；等待超时；事件／日志占用计入容量；终态闭包含失败与未启动任务 |
| H3 | 恶意日志指令、伪造证据、过期状态、非法 JSON、超大响应、模型失联；未授权数据不得进入模型请求 |
| H4 | 凭据不进入 worker／日志；实际宿主调用、卸载、重连；宿主与插件版本固定后的契约测试 |

H0—H2 完成只可表述为“已有体系的本地规则无人值守可用”；H3 经真实 agent 实测后才称 agent 闭环；H4 完成才称 DeepSeek 插件可用。仍不能称所有材料、服务器或自适应科学研究已完成。首轮真实测试继续使用预先明确的短程 CPU 预算，不为做故障测试扩大计算规模。
