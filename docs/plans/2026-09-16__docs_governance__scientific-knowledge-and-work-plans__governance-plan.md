# MateriaSim 科学知识库与工作计划增补方案

## 1. 目标与本轮边界

建立一套能够长期回答以下问题的文档体系：为什么选择某种模型和算法，何时适用，参数如何确定，平台是否已接入，证据支持到什么程度，以及下一步应开发或验证什么。

不是把所有 Markdown 放进同一个目录，也不是把 GROMACS 手册复制一遍。目标是形成以下闭环：

```text
文献／官方资料 → 科学知识与适用边界 → 模型、场景、协议与分析选择
                         ↓                        ↓
                    工作计划／验证设计 → 代码、配置及研究执行
                         ↑                        ↓
                    新问题与修订 ← 经审查的运行证据与结论
```

方案编写时仅新增本文件；随后用户授权先 commit 备份再实施。已提交备份 a044693 并完成第 16 节的文档首版；没有迁移原始数据、新增依赖、改变科学参数、运行 MD 或推送。

知识库可以先建立，不必等待选定具体聚合物或纳米材料。但具体材料的参数、可用协议和科学验证结论，必须等待实际模型与证据，不能由通用知识页代替。

## 2. 调研结论：借鉴 MyQuant 的治理，不照搬量化知识

参考对象是本机 `quant-platform/myquant-workspace` 的实际文档，而非仅看目录名。主要借鉴如下。

| 已观察到的机制 | MateriaSim 的采用方式 | 不照搬的部分 |
|---|---|---|
| Work Plans 单一根目录、按职责分组、元数据、索引与迁移表 | 保留已有 `docs/plans/`，补统一规则与索引 | 不再建立另一套根级 `work_plans/` |
| 知识总入口与知识归属，方案和历史报告不作为当前事实 | 建立单一 `docs/knowledge/`，一项知识一个规范归属 | 暂不为每个 Python 子模块建立独立知识库 |
| 数学文档区分理论审查、实现核对和验证 | 扩展为科学假设、算法定义、实现映射、数值与采样证据、材料适用性 | 不把量化领域的信息时点规则照抄为 MD 科学标准 |
| 已完成计划提取稳定知识，保留历史来源 | 增加知识回写清单及替代关系 | 不因迁移成功删除原文、模型或 Run |
| 能力注册、文档与代码关系校验 | 先建立轻量能力矩阵和静态检查 | 暂不引入多层模块注册服务、向量数据库或自动审批 |

尤其要调整一个优先级：**代码决定“程序实际做了什么”，但不决定“科学上什么是正确的”。** 科学原理、模型有效性与实验对照必须有独立依据。发现代码与理论不一致时记录分歧并形成修复任务，不通过修改知识页来证明代码正确。

来源和查阅范围见第 15 节；MyQuant 仅作为组织方式来源，不成为 MateriaSim 的运行依赖。

## 3. 项目现状与主要缺口

当前已有 README、使用指南、项目内 Skill、五份架构／实施方案和工程验收记录，但还没有正式的 `docs/knowledge/`，工作计划也没有统一索引和迁移表。

现有资料存在三种需要治理的情况：

1. 科学说明、未来设计与已实现功能分散在指南、方案和代码中，缺少稳定的知识归属。
2. 旧方案的状态和覆盖范围不同；较新框架交付覆盖了部分旧任务，但不代表旧方案的全部材料场景均已完成。
3. 工程测试与短测已有证据，科学模型适用性、充分采样和新材料支持不能据此推定。

本方案的实际能力基线来自[根 README](../../README.md)、[流程与工具边界指南](../guides/md-workflow-and-tool-boundaries.md)及其源码映射：现有 ZIL/CAT/ANI 的受限装配与水体系、运行管理和两类接触分析可复用；混合溶剂、聚合物、纳米材料、固相／界面仍需接入与验证。Mac CPU 的历史实测不能替代 Linux/GPU 验收。本轮未重新运行这些验收。

## 4. 原来的“五类内容”怎样融入知识库

这五类不是互斥的知识目录，而是同一项能力的不同维度。例如 RDF 同时包含原生算法、可调分析参数、可复用分析配置和项目接入状态。

| 原有分类 | 知识库记录什么 | 实际内容的规范归属 |
|---|---|---|
| GROMACS 自带，不重写 | 原理、适用条件、上游命令／版本、输入输出语义和限制 | 算法知识页；外部实现仍由 GROMACS 维护 |
| 随研究经常调整 | 参数的物理意义、单位、约束、敏感性与调整后的验证要求 | 知识页解释语义；具体数值由实验／研究配置和冻结输入持有 |
| 预先配置的组件 | 模型身份、来源、兼容性、适用范围、选择理由与证据 | 知识页说明；坐标、拓扑和协议等可执行资产由 `catalog/` 等现有归属持有 |
| 项目已经有的 | 对应实现、版本、测试与实测范围 | 平台能力矩阵，链接代码和验收证据 |
| 项目还需开发的 | 缺口、接入路线、依赖条件、验收目标 | 能力矩阵标记缺口；实施工作进入计划，不写成已经可用的事实 |

每项知识不强制填满全部维度。纯理论页可以没有本地代码；材料参数页可以没有自研算法；未接入的上游能力必须明确标注未接入。

### 4.1 保留指南作为入口，不建立第二份流程真相

[MD 工作流程与工具边界指南](../guides/md-workflow-and-tool-boundaries.md)继续回答“从哪里开始、按什么路线做”。实施时逐项提取需要长期维护的理论与定义，再由指南链接知识页：

- 模型与相互作用选择 → 模型知识、力场兼容性、证据要求。
- 组成、边界与装配 → 组成换算和场景知识。
- 协议 → 积分、约束、温压控制、平衡判断等算法知识。
- 分析 → 观察量定义、估计方法和误差知识。
- 项目支持程度 → 平台能力与验证矩阵。

指南保留必要概述；详细公式、参数解释和适用边界只设一个规范维护位置，不同时完整复制到指南、Skill 和知识页。

### 4.2 参数必须按影响分级

| 调整类别 | 例子 | 知识库要求记录的后果 |
|---|---|---|
| 研究条件 | 数量、配比、链长、温度、盐条件 | 新研究条件；核对模型适用范围、组成与平衡需求 |
| 物理模型 | 质子化状态、力场、电荷、交叉作用、水模型 | 模型变更；重新审查科学依据和相关验证，不能只以不报错为依据 |
| 数值近似与协议 | 步长、约束、截断、耦合方式和参数 | 评估数值误差、系综和目标观察量影响；不得作为通用“稳定运行旋钮” |
| 采样与估计 | 时长、种子、重复数、分析窗口、接触阈值 | 记录采样设计和估计定义变化，重新评估可比性与不确定性 |
| 计算实现 | CPU/GPU、线程、引擎版本 | 工程与数值一致性验收；不要求逐位相同，也不能假定更换实现无影响 |

具体合法字段仍以当前程序 schema 为准；不能把知识页中的建议键名直接加入严格实验 JSON。

## 5. 目标目录与文档边界

以下为拟建结构，不表示已经存在；按有实质内容的主题逐步创建，不创建空目录或空页面。

```text
docs/
  guides/                       # 如何使用；保留现有入口
  plans/                        # 唯一工作计划根
    README.md                   # 规则与生命周期
    INDEX.md                    # 计划目录和范围摘要
    MIGRATION_MAP.md             # 来源、现位置、替代关系
    templates/                  # 计划模板，不作为活动计划收录
    governance/                 # 后续新计划按职责分组
    framework/ models/ scenarios/ analysis/ execution/
  knowledge/
    README.md                   # 按研究问题导航，唯一总入口
    INDEX.md                    # 知识条目、主题、状态和适用范围
    foundations/               # 物理基础、单位、系综、分辨率和边界
    algorithms/                # 算法与估计器，不按提供者分裂同一原理
    models/                    # 化学身份、力场、模型兼容与材料模型
    scenarios/                 # 溶液、聚合物、固相、界面等方法路线
    platform/                  # 当前能力、契约和工具映射
    verification/              # 数值、采样、模型验证的方法与标准
    references/                # 文献来源登记、阅读笔记和争议
    decisions/                 # 已采纳的重要方法／工程决策
    governance/                # 维护与证据晋升规则、知识提取记录
    templates/                 # 科学、算法、模型、场景等模板
  validation/                  # 原有验收记录，仍保留其历史属性
  ideas/                       # 有实际探索内容后再建立；不作为规范结论
```

边界补充：

- 知识库不保存虚拟环境、完整轨迹、检查点和大规模原始数据。
- `catalog/` 持有资产，`studies/` 持有研究定义，源码持有行为，Run 持有冻结证据；知识页建立解释与链接，不复制它们。
- `docs/architecture/migration_map.json` 是已有代码／资产迁移资料，不覆盖为知识或计划迁移表。
- 当前五份计划第一阶段保留原路径。子目录主要承接新增计划；是否移动旧文档另行决定，避免破坏已有链接。
- 知识文件采用稳定的主题名，例如拟建 `algorithms/component_contacts.md`；不按日期、完成状态或作者建目录。计划文件保留日期以体现历史。

## 6. 元数据、状态和事实归属

### 6.1 工作计划标准

新计划文件名：`YYYY-MM-DD__<domain>__<short-topic>__<plan-kind>.md`。已存在名称和 `doc_id` 不为美观机械重命名。

必需元数据采用本方案头部的完整字段：`type`、`status`、`plan_kind`、`owner`、`module`、`domain`、`created`、`last_updated`、`canonical`、`doc_id`、`source_path`、`supersedes`、`superseded_by`、`related_kb`、`related_code`、`rag_exclude`，并记录明确的范围和实施状态。

- `status`：`draft / active / blocked / completed / superseded / rejected / archived`。
- `plan_kind`：`architecture-plan / implementation-plan / migration-plan / refactor-plan / cleanup-plan / research-plan / validation-plan / execution-guide / governance-plan`。
- `canonical` 只表示该文档是此计划的规范版本，不代表设计已经批准或实现。
- `completed` 只表示声明范围内交付和验收完成；未覆盖的科学验收或平台验收须列为后续事项，不能隐含取消。
- 计划默认 `rag_exclude: true`，防止未来检索把设计当事实；当前这只是治理字段，不代表项目已存在 RAG 服务。

### 6.2 知识页标准

拟采用以下最小元数据，字段只用于文档，不直接扩展运行配置：

```yaml
type: knowledge
doc_kind: algorithm
doc_id: materiasim.kb.algorithms.component_contacts
title: 组分接触计数的定义与实现映射
status: draft
canonical: true
owner: MateriaSim
created: 2026-09-16
last_updated: 2026-09-16
scope: 当前分子对接触计数；不等同于吸附自由能或动力学常数
source_refs: []
related_code: [src/materiasim/analysis/component_contacts.py]
related_assets: []
related_plans: []
supersedes: []
superseded_by: []
review:
  theory: not_reviewed
  implementation: not_checked
  evidence: not_assessed
limitations: []
rag_exclude: true
```

示例为空的字段是模板，不是可发布的最终知识页。必需依据未补齐时保持 `draft`，不得用模板页面充当完成数量。

知识文档状态拟定为 `draft / current / deprecated / superseded / archived`。`current` 表示在声明范围内审查过的当前知识，不意味着所有模型或设备已验收；规范归属与成熟度必须分开。

### 6.3 至少区分四种审查结论

| 维度 | 需要回答的问题 | 不应推导的结论 |
|---|---|---|
| 理论／资料审查 | 原理、定义、假设和来源是否核对？存在哪些争议？ | 有论文不代表适用于本材料 |
| 实现映射 | 上游提供什么？本项目接入什么？代码是否符合声明语义？ | GROMACS 有不代表 MateriaSim 已封装 |
| 数值与采样证据 | 哪些版本、体系、窗口和重复经过什么检查？ | 短跑成功不代表充分采样 |
| 模型适用性 | 对哪些材料、状态、性质有验证？未知边界是什么？ | 一种性质验证不能覆盖所有性质和材料 |

一篇包含多个结论的文档使用“结论—来源—范围—状态”表，不用一个总体 `verified: true` 掩盖局部缺口。`not_applicable` 必须解释理由；不适用和未完成不是同一状态。

纯理论或上游参考页可以经充分资料审查后成为 `current`，即使本项目未实现对应能力；但必须明确“未接入／未本地验证”。反之，代码和单元测试齐全也不自动获得科学有效性结论。

知识页和能力矩阵不构成生产审批，不自动修改[用途门禁](../../src/materiasim/specs/purpose.py)。当前用途证据是本地可追溯声明，不是认证签名；文档规则不应暗中改变这一安全边界。

## 7. 知识模板：不仅解释代码，更解释算法与科学

### 7.1 科学基础／算法页的必需内容

1. **问题和目标量**：要计算什么，为什么需要它，哪些问题不适用。
2. **物理假设**：分辨率、系综、边界、平稳性、相互作用模型等。
3. **数学定义**：核心方程、变量、单位和符号约定；必要的推导或近似来源。
4. **离散实现与估计器**：从理论量到轨迹／样本如何计算，权重、归一化、窗口和缺失条件。
5. **边界情况**：周期跨越、分子完整性、排除规则、有限尺寸、零样本和不可识别情况。
6. **参数语义**：默认值来自哪里，哪些应由研究指定，改变它们影响什么。
7. **实现映射**：GROMACS／外部库／MateriaSim 各做什么；版本、输入输出、可用程度。
8. **验证设计**：解析例子、受控小体系、参考实现和真实体系分别能证明什么。
9. **证据和分歧**：通过与失败的证据，理论与实现差异，尚未解决的问题。
10. **来源**：准确到版本、章节、方程或论文位置，而不只是一个主页链接。

不要求为所有成熟算法重写完整教材推导，但必须写清影响使用决策的公式、近似和局限。例如 RDF 的归一化、排除规则和表面体系限制，MSD 的拟合区间与适用条件，不能只写“调用对应命令”。[GROMACS RDF 文档](https://manual.gromacs.org/current/onlinehelp/gmx-rdf.html)、[MSD 文档](https://manual.gromacs.org/current/onlinehelp/gmx-msd.html)

### 7.2 模型、场景与验证页

| 页面类型 | 必需的专属内容 |
|---|---|
| 材料／模型 | 化学身份、拓扑与参数来源、分辨率、版本、端基／质子化／表面状态、兼容性、参数化方法、验证对象和失效边界 |
| 场景 | 研究问题、组成与几何、边界、准备路线、协议选择理由、可能分支、应观测的平衡与采样信号、已实现与缺口 |
| 分析方法 | 选择对象、数学估计器、单位、窗口、相关性、跨重复汇总和误差定义；不把波动当均值误差 |
| 验证方法 | 验证目的、参考依据、判定量、预先确定的阈值及理由、失败解释、适用范围和证据格式 |
| 文献笔记 | 原文报告、作者假设、本地推断分开；主文／SI／数据的阅读范围、可支持和不可支持的结论 |
| 平台契约 | 实际输入输出和限制、源码与测试定位、外部工具边界；不取代算法原理页 |

不将“最小化→NVT→NPT”写成所有材料的强制模板。场景页要解释何时需要、可省略或必须改变某个步骤；协议资产只有经过相应审查后才能被推荐。[GROMACS 体系准备指南](https://manual.gromacs.org/current/user-guide/system-preparation.html)

### 7.3 首个完整示范：组分接触，不停留在抽象模板

建议首篇算法知识使用已存在的[组分接触分析](../../src/materiasim/analysis/component_contacts.py)，并与[水化分析](../../src/materiasim/analysis/hydration.py)对照。

当前分子对接触计数可解释为：对帧 \(t\)，若所选两组原子中存在距离不超过阈值 \(r_c\) 的跨分子原子对，就把对应的无序分子对记为一个接触；同一分子对不重复计数，不计分子内接触。

\[
\mathcal C_t = \left\{\{m(i),m(j)\}: i\in A,\ j\in B,\ m(i)\ne m(j),\ d_{\mathrm{PBC}}(i,j)\le r_c\right\},
\qquad C_t=|\mathcal C_t|.
\]

\(m(i)\) 是原子所属分子的标识；\(d_{\mathrm{PBC}}\) 按分析所用周期盒计算；\(C_t\) 无量纲。源码把配置的 nm 阈值乘以 10 转换到 MDAnalysis 距离调用使用的 Å。

这一页必须另外说明：

- 水化分析统计所选接触水分子的集合，并不等于原子对数，也不应直接当作上述分子对计数。
- 当前两类分析没有自动平衡截断；水化分析报告的帧间总体标准差不是均值标准误或置信区间，组分接触分析则报告直方图和均值，并未给出置信区间。
- 重复接触不能自行解释成结合自由能、驻留时间或吸附平衡常数；这些需要新的定义、估计与验证。
- 本次源码核对只支持对实现的描述，不构成该阈值对某种材料科学合理的证明。

后续应核查／补充的测试包括：周期边界两侧接触、同分子排除、同一分子对多原子接触去重、选择集合重叠、阈值附近行为及单位换算。这里是测试设计，不声称本轮运行了这些测试。

## 9. 来源、结论与证据的关联

### 9.1 来源登记与阅读深度

每个正式引用登记稳定来源 ID，并记录：作者／维护者、题名、DOI 或官方 URL、发表／软件版本、查阅日期、相关章节／方程、主文／SI／数据阅读范围、许可或访问限制及适用结论。

`current`、`stable`、默认分支 URL 会变化。正式算法页应优先锁定版本／提交或记录当时版本与定位，不能用一个动态链接暗示长期行为一致。

文献来源建议单一登记，知识页引用来源 ID；初期可用 Markdown 来源表，后续确有机械校验需求再转换为结构化登记，不能长期维护两份相互竞争的来源清单。未阅读全文只能说明摘要支持的内容，不伪造 SI、数据或细节核查。

### 9.2 结论级记录

重要结论至少关联以下信息：结论本身、结论类型、范围、来源、审查状态、局限和相反证据。结论类型区分文献报告、本地复现、模型预测、方法定义和研究假设。

本地证据应能定位到：研究／Run 身份、模型与输入哈希、代码及工具版本、平台、协议、分析选择与窗口、重复和种子、指标及单位、对照与阈值依据。证据不可用或文件失联时明确标记，不能从历史摘要重建一个“通过”的记录。

知识库保存审查过的结论摘要和证据定位，不拷贝轨迹。运行证据仍不可变；新解释或改进产生新的分析／验证记录，不倒改旧报告。普通运行不自动修改知识页、计划索引或批准状态。

## 10. Work Plan 的生命周期与知识回写

每份活动计划明确目标、非目标、依据、改动范围、工作项、验证标准、风险、授权边界和知识回写清单。工作项的主状态只维护在所属计划，索引提供导航和摘要，不建立第二套独立任务账本。

建议流程：

1. **立项**：从知识／能力矩阵发现缺口，记录相关知识 ID、源码和证据。
2. **实施**：按范围修改代码、资产或文档，及时标记已实现与未验证的区别。
3. **验收**：按原定范围记录真实检查；未通过、未运行和环境限制单列。
4. **知识提取**：稳定定义和边界写回规范知识页；实际入口写回 README／指南；纯历史决策留在计划。
5. **收口**：填写 `Knowledge Extraction` 节，列知识落点、保留的历史内容、未决问题和后续计划，再决定是否 `completed`。

旧计划不必为了新 schema 全文重写。先补必要元数据与范围说明，保留历史日期；没有可靠原始日期时保留来源，不捏造创建时间。

## 12. Agent 与研究工作如何使用
