# 多场景、多组分分子模拟平台升级方案

## 1. 建议与目标

建议将现有的两个专用水化模拟项目，升级为“共享模拟核心 + 版本化组分库 + 场景配方 + 独立实验”的材料模拟平台。输入描述研究对象、组分、组成和环境；平台检查模型适用性，生成体系及运行计划，调用原生模拟引擎，最后按问题类型分析结果。

目标是能够逐步组合小分子、聚合物、溶剂、离子、纳米颗粒和表面，覆盖单分子、单链、聚合物溶液、聚合物/小分子混合溶液，以及聚合物/纳米材料/小分子共同体系。平台仅支持 macOS/Linux；项目编排使用 Python，集群提交可以使用 POSIX shell，不引入 PowerShell、Windows 路径或 WSL 依赖。

推荐的实施顺序（历史初始蓝图；P1a 后按下述修订说明执行）：

1. 将现有 ZIL、CAT/ANI 两个体系迁移成可复现的基准案例。
2. 支持已验证小分子、溶剂与离子的多组分组合。
3. 增加一个经过专项验证的聚合物家族，贯通单链、多链溶液和聚合物/小分子体系。
4. 增加一种明确表面化学的纳米材料，先验证二元界面，再形成完整混合体系。
5. 按研究尺度增加 Martini 粗粒化；按势函数需要增加 LAMMPS。
6. 在配置和运行核心稳定后提供可视化选择界面。

“支持多种组分”应当意味着：已登记的模型可以在验证过的组合范围内使用。未覆盖的化学结构、跨组分相互作用和实验条件，需要新增参数研究与验证记录，不能仅凭生成了拓扑文件就显示为可正式模拟。

本文中的长期目录树、配置字段、命令和版本标识仍为拟议设计；第 12.3 节的 P1a 子集已落地，实际接口以 [materials_simulation/README.md](../../materials_simulation/README.md) 为准，不能直接使用本文其余示例。本文本身不构成新模型或正式科学模拟结果的验收记录。

第 12.3 节的“最小可运行框架”是已完成 Mac CPU 工程验收的 P1a 范围，不再作为下一轮升级的终点。第 6.3 节是长期责任划分，不是第一轮必须创建的全部目录。框架验收不等于完成本方案所有场景。

### 1.1 P1a 后实施范围修订（2026-09-14，修订 5）

后续以[多组分＋多场景实施方案（修订 2）](2026-09-14__multicomponent-multiscenario__implementation-plan.md)为唯一具体实施依据：M1 核心契约/历史读取 → M2 既有资产共用核心 → M3 多组分液体及选定混合溶剂 → M4 聚合物溶液与熔体 → M5 真实晶体固相及 LAMMPS → M6 表面/颗粒与复杂混合。M4/M5 在共同契约稳定后可分别推进。

本轮新增完整相互作用模型包、晶胞与结构交接、阶段产物和分场景科学验收；无水周期盒仅为回归，不代表固体或真空支持。LAMMPS 前移到 M5 的真实固相交付，不创建空适配器。所有新增能力仍未实施，文档修订不授权安装或计算。

本文件下文的 P 阶段、初始支持顺序和 P1a 范围保留作历史蓝图；与新实施方案不同之处，以其 M1—M6 范围、顺序和验收定义为准。长期科学边界仍有效，既有 README/验收报告只记录实际能力，不回写为新阶段已完成。

### 2.2 组织上的调整

按课题整理目录仍适合研究案例；新增共享模拟核心后，通用编排、构建和分析代码集中维护。每个课题只保留组分引用、研究问题、协议、输入和报告，避免每增加一种体系就复制一份生产脚本。

当前工作区没有统一 Git 仓库，两个旧复现目录仅剩 `.git`，且其中一个分支状态异常。实施前应清点并备份这些历史数据，再建立新核心的版本管理，不能把它们当作空目录删除。

## 3. 场景范围与支持层级

场景由“组分 + 连接关系 + 几何布局 + 物理模型 + 运行协议 + 观察量”共同决定。组分数量不是唯一复杂度指标；短链稀溶液与高分子量浓溶液，即使组分类别相同，也需要不同平衡方法和计算预算。

| 场景 | 需要输入 | 主要输出 | 建议支持顺序 |
|---|---|---|---|
| 单个小分子真空/隐式环境 | 化学结构、电荷、边界与环境模型 | 构象、能量、内部几何 | 真空先用于诊断；隐式模型另行验证 |
| 小分子水溶液/离子对 | 已参数化溶质、水、离子、盒子与组成 | 水化、RDF、氢键、离子接触 | 第一版，继承现有案例 |
| 多小分子混合溶液 | 多种溶质/溶剂、数量或浓度 | 组分分布、缔合、扩散 | 第一版的扩展 |
| 聚合物单链 | 重复单元、连接位点、链长、端基、立构及溶剂 | 回转半径、端到端距离、局部构象、水化 | 第二版，先一个线性聚合物家族 |
| 聚合物多链溶液 | 链数、分子量分布、溶剂/盐、浓度 | 链间接触、聚集、溶剂化、构象分布 | 第二版 |
| 聚合物与小分子溶液 | 上述输入及添加剂/药物/功能小分子 | 接触、富集、竞争吸附、扩散 | 第二版；力场组合需验证 |
| 聚合物熔体、共混物 | 链分布、温度、密度构建方案、混合比 | 密度、链构象、结构与慢松弛 | 后续扩展，不沿用稀溶液平衡模板 |
| 纳米颗粒/平面表面与溶剂 | 晶型、尺寸、晶面、表面化学、动力学处理 | 界面密度、吸附、润湿相关量 | 第三版，先一个材料家族 |
| 聚合物 + 纳米材料 + 小分子 + 溶液 | 全部模型及跨组分兼容证据 | 竞争吸附、包覆、桥连、分散与聚集 | 第三版最终集成目标 |
| 接枝聚合物、刷层、交联网络 | 接枝位点/密度、跨组分共价连接或交联图 | 刷层高度、网络结构、溶胀相关量 | 独立高级场景 |
| 成键/断键、聚合反应、腐蚀 | 反应问题、适用反应势和验证集 | 指定反应过程相关量 | 专项研究，非基础平台能力 |

应用界面应显示三种能力状态：**已验证可用、需要参数验证、不支持**。不能把未来场景列为已交付功能。

## 4. 必须先解决的科学建模问题

### 4.1 聚合物不是把小分子坐标复制多次

聚合物描述至少包含：重复单元的化学结构与原子映射、头尾连接原子、键型、端基、聚合度、支化/环状连接、序列和立构规整性。加成聚合的产物重复单元与游离单体结构可能不同；连接时需要明确删去哪些原子、改变哪些键和价态。

共聚物应区分无规、交替、嵌段和明确给定序列。仅给 A/B 摩尔比不能唯一决定链结构；无规序列需要生成规则、随机种子和实际生成的序列文件。分散体系需要保存每条链的聚合度，而不仅保存平均分子量。

polyply 将参数拓扑生成和坐标生成作为两个独立问题处理，并使用已有的残基块与连接规则组装聚合物。它适合作为 GROMACS 聚合物构建路线，但不会为任意未知重复单元自动建立可靠力场。官方代码库列出的参数家族包括 GROMOS、OPLS、Parmbsc1 和 Martini，具体聚合物覆盖范围仍需逐个核对。[polyply 论文与官方库](https://www.nature.com/articles/s41467-021-27627-4)。[^1][^2]

本平台应把“化学组装正确”和“参数覆盖正确”设为不同检查。对于自定义聚合物，先在封端单体、二聚体和短低聚物上检查连接区域的键角、二面角、电荷及构象，再扩展链长。不能把自由单体的 AM1-BCC 电荷直接复制到聚合后的所有重复单元。

### 4.2 初始装填和平衡态是两回事

PACKMOL 能将不同分子放入指定空间区域，并控制分子间最小距离；它需要输入各类分子的坐标。其装填成功只说明几何约束达到要求，不表示已完成参数化或热力学平衡。官方当前文档支持正交周期盒，任意三斜盒不能默认沿用同一构建路径。[PACKMOL 用户指南](https://m3g.github.io/packmol/userguide.shtml)。[^3]

聚合物需要另外检查链穿越、异常拉伸、环的连接与拓扑、局部高能构象。浓溶液与熔体可能需要逐步压实、模型适配的软排斥松弛或退火；这些处理必须完整记录。改变链穿越条件或使用非物理加速过程所得轨迹，不能直接作为动力学观察量的生产段。

### 4.3 纳米材料必须明确表面模型

同一个“SiO₂ 颗粒”名称不能唯一决定模拟模型。至少应描述晶体/无定形结构、颗粒几何、表面终止、羟基密度、质子化/去质子化、净电荷、反离子、缺陷，以及是否接枝其他分子。

金属材料还可能涉及极化与镜像电荷；碳材料可能涉及边缘终止、氧化程度和选定势函数。只从 CIF/XYZ 生成坐标，并不能生成这些物理模型。

INTERFACE Force Field（IFF）提供无机/有机界面的参数和表面模型。原论文强调与母体力场的函数形式及组合规则保持一致；官方分发包含 PCFF、CHARMM、CVFF 等分支，材料和示例覆盖并不完全相同。因此应选择具体的“材料 + IFF 分支 + 有机物/水/离子模型”组合，而不是增加一个统一 `forcefield: IFF` 开关。[IFF 原论文](https://pubmed.ncbi.nlm.nih.gov/23276161/)、[官方参数库](https://github.com/hendrikheinz/INTERFACE-force-field-and-surface-models)。[^4][^5]

例如，官方页面中的 PEO 示例标为 PCFF 分支，而 GROMACS 导出链接并不意味着所有 PCFF 函数和交叉项都可无损转换。参数分支与引擎适配应在纳米材料阶段明确核对。官方页面同时混有旧版发布信息和后续扩展，实际采用时必须锁定文件版本与哈希。[IFF 分发与覆盖说明](https://bionanostructures.com/interface-md/)。[^6]

### 4.4 力场兼容是多组分系统的核心门槛

每个组件单独可运行，不代表把它们放在同一盒子里后结果可信。必须核对：

- 全原子、联合原子、粗粒化分辨率及各自映射。
- 势函数形式：LJ 12-6、LJ 9-6、Buckingham、多体势等。
- LJ 组合规则、显式交叉参数和例外项。
- 电荷模型、介电设置、水模型、离子参数及其匹配关系。
- 1–4 缩放、排除表、特殊配对和拓扑生成规则。
- 单位、约束、虚拟位点，以及引擎是否支持全部功能。
- 经过验证的温度、组成、表面化学和观察量范围。

GROMACS 拓扑中的 `[defaults]` 包含组合规则、生成配对和 1–4 缩放等全局设置；混合参数时必须检查这些约定以及显式例外，不能仅把不同来源的 `.itp` 拼接到一起。[GROMACS 拓扑格式](https://manual.gromacs.org/current/reference-manual/topologies/topology-file-formats.html)。[^7]

对多体势，风险不止来自成对交互。LAMMPS 官方特别说明，不能为了覆盖缺失元素而随意拼接多个多体势；EAM 嵌入项、多原子组合和电荷平衡都可能因此不一致。[LAMMPS hybrid 说明](https://docs.lammps.org/pair_hybrid.html)。[^8]

建议建立“兼容模型组合包”：记录完整组分模型、交叉作用、验证案例和适用范围。成对兼容矩阵只是快速筛查，最终还需检查整套组合；三元体系可能出现二元测试未覆盖的行为。

### 4.5 分辨率必须由研究问题决定

| 路线 | 适合的研究目标 | 主要限制 |
|---|---|---|
| 全原子固定拓扑 MD | 局部水化、特定氢键、官能团接触、原子级界面结构 | 大盒子、长链和慢聚集过程成本高；成键关系通常固定 |
| 联合原子模型 | 某些聚合物/有机液体的结构与物性 | 参数家族和观察量需专项验证，不能自动混用其他模型 |
| Martini 等粗粒化 | 更大尺度链构象、聚集、相分离和包覆形态 | 原子细节被平均化；时间尺度和映射需要校准 |
| 专项反应性/量化路线 | 指定成键、断键、反应或电子结构问题 | 需要独立的适用参数、验证集和预算 |

Martini 3 是面向较大时空尺度的粗粒化模型。它可以作为长链和复杂混合体系的另一条路线，但应建立独立组分库和分析协议。[Martini 3 原论文](https://www.nature.com/articles/s41592-021-01098-3)。[^9]

尤其不能把粗粒化水珠计数直接乘某个系数，作为当前 ZIL 原子级第一壳层“结合水数”。官方 Martini 溶剂示例本身就体现了水珠与真实水分子数的区别；跨分辨率观察量需要单独定义与标定。[Martini 溶剂模型示例](https://cgmartini.nl/docs/downloads/example-applications/solvent-systems.html)。[^10]

如果后续采用“粗粒化平衡 → 回映全原子”，必须具备逐组分映射文件，并在回映后重新进行全原子松弛与平衡；粗粒化时间与全原子时间不拼接成一条连续动力学轨迹。[Backward 官方教程](https://cgmartini.nl/docs/tutorials/Martini3/Backward/)。[^11]

### 4.6 pH、吸附和聚合反应的边界

基础版本的 `pH` 只用于记录实验条件与所选择的质子化/表面状态，不自动实现恒 pH 动力学。对于带电聚合物，要指定电离度及电离位点分布；对于纳米表面，要指定相应表面模型和反离子。

“聚合物链模拟”默认模拟已生成的聚合物，不等于模拟聚合反应。接枝和交联也需要显式连接图与跨连接参数。反应性模拟作为独立协议加入；ReaxFF 需要适合目标化学空间的参数集及相应电荷处理，而不是通用升级按钮。[LAMMPS ReaxFF 文档](https://docs.lammps.org/pair_reaxff.html)。[^12]

观察到若干接触事件不等于得到吸附自由能。若目标是吸附/解吸自由能，需要另外设计反应坐标、采样窗口和误差评估；基础平台先输出接触和结构统计。

## 5. 技术选型与接入顺序

以下是架构选择，表示推荐职责与条件，不表示所有工具已安装或完成本机兼容性验证。

| 工具 | 职责 | 接入建议 | 不承担的职责 |
|---|---|---|---|
| GROMACS | 现有与新增非反应性体系的生产模拟 | 首个正式引擎，继承已有经验 | 自动为未知组分提供参数 |
| RDKit + AmberTools + ParmEd | 有机分子结构处理、GAFF2 路线及格式处理 | 保留为独立参数化流程，先审计 macOS/Linux 环境 | 无条件处理纳米材料和所有聚合物 |
| polyply | 由已知单元/连接规则构建聚合物拓扑与坐标 | 聚合物阶段的首选构建器 | 自动验证新单元的物性 |
| PACKMOL | 多种溶质、溶剂和空间区域的装填 | 混合体系阶段接入 | 力场生成、平衡采样 |
| MDAnalysis + NumPy/SciPy | 轨迹、选择、统计与报告 | 提取现有分析代码并扩展 | 隐式猜测分子身份与物理模型 |
| ASE | 晶体、表面和颗粒的结构操作 | 纳米材料阶段按需接入 | 自动选择表面电荷或界面力场 |
| LAMMPS | 特殊材料势、多体势、特定 PCFF/材料路线 | 有明确模型需求时增加第二引擎 | 自动修复不兼容的混合势 |
| Moltemplate | LAMMPS 复杂拓扑和层级组装 | 与 LAMMPS 路线配套评估 | 官方明确不提供通用自动原子类型分配 |
| mBuild/Foyer/GMSO | 复杂化学连接、原子类型规则与拓扑组织 | 在 polyply 无法覆盖实际任务时评估 | 首版全部引入并并行维护 |
| OpenMM | 单点能量/力交叉验证、特定模型原型 | 延续历史验证角色，不急于增加第三套生产链路 | 保证不同引擎逐步轨迹完全相同 |
| RadonPy | 聚合物物性自动化与批量计算 | 借鉴验证、平衡和物性流程；将来可做专项适配 | 直接作为所有纳米混合体系的统一后台 |

mBuild 提供层级组装与连接能力，Foyer 着重明确原子类型规则；这两者适合复杂构建，但会增加依赖与转换验证成本。[mBuild](https://mbuild.mosdef.org/en/stable/)、[Foyer](https://foyer.mosdef.org/en/stable/)。[^13][^14]

ASE 提供纳米颗粒/团簇构建接口，可以处理结构部分。[ASE 官方文档](https://docs.ase-lib.org/ase/cluster/cluster.html)。[^15] Moltemplate 适用于 LAMMPS 的全原子和粗粒化体系组装，官方说明其依赖 Bourne shell 与 Python；这符合 macOS/Linux 要求，但仍需审查模型输入和原子类型。[Moltemplate 官方说明](https://moltemplate.org/)。[^16]

RadonPy 的研究工作证明了围绕聚合物重复单元、自动 MD 与物性计算形成流程的可行性；其项目有自己的依赖、参数化和平衡约定。因此本项目更适合借鉴与接入具体能力，而非立即替换全部现有流程。[RadonPy 论文预印本及发表信息](https://arxiv.org/abs/2203.14090)、[官方代码库](https://github.com/RadonPy/RadonPy)。[^17][^18]

OpenFF 可作为后续小分子模型候选，但首版已有 GAFF2 历史基准，暂不增加第二套自动小分子参数路线。它的官方定位也不能作为任意纳米材料参数覆盖的保证。[OpenFF FAQ](https://openforcefield.org/community/faq/)。[^19]

## 6. 目标软件架构

### 6.1 核心对象

建议定义六类有版本的对象：

| 对象 | 回答的问题 | 核心内容 |
|---|---|---|
| 组分 `Component` | 这是什么物质及化学状态？ | 化学结构、连接图、序列、端基、表面状态、组成、身份 |
| 模型 `Model` | 用何种分辨率和参数表示？ | 力场来源、参数文件、原子映射、函数形式、许可、验证范围 |
| 场景 `Scenario` | 如何组合、放在哪里？ | 组分数量/浓度、盒子、几何区域、连接关系、边界 |
| 协议 `Protocol` | 如何平衡和采样？ | 阶段、温压控制、约束、步长、目标量与接受标准 |
| 实验 `Experiment` | 要比较什么？ | 科学问题、变量、对照组、重复设计、观察量定义 |
| 运行 `Run` | 具体执行了哪一次？ | 解析后输入、哈希、软件与硬件、种子、阶段状态、结果 |

同一化学组分可以有不同模型，例如同一条 PEO 链的全原子与 Martini 表示；它们共享化学来源，不共享参数或结果解释。纳米材料的羟基化程度和聚合物端基变化通常改变组分身份，不能仅视为显示名称变化。

### 6.2 数据流

```text
实验定义 + 组分库 + 场景模板
               ↓
化学状态与组成解析
               ↓
模型覆盖 / 全局兼容 / 资源检查
               ↓
冻结组分与参数，生成构建计划
               ↓
坐标构建 → 装填 → 最终身份映射与构建检查
               ↓
编译为 GROMACS 或已支持的 LAMMPS 输入
               ↓
EM / 分阶段平衡 / 正式采样 / 检查点续跑
               ↓
质量检查 → 专项分析 → 独立重复比较
               ↓
结果清单、报告与可追溯物性数据
```

任何检查失败，都应明确给出缺少的模型、参数或证据。不能自动改力场、换水模型、减少组分或提高 `maxwarn` 来凑出可运行输入。

不再只增加课题目录，而是新增一个独立模拟平台目录；现有 ML 课题保持独立。下列目录按阶段创建，不预先堆放空实现。


### 6.4 模块边界与数据所有权

组分库只保存有明确版本和来源的资产；实验引用资产版本，不自行复制散落的参数。引擎层消费已经冻结的构建输入，不临时决定科研参数。执行层管理进程与任务状态，不判断科学结果好坏；分析层根据质量状态生成带限制的报告。

第一版用本地文件、JSON 清单和包内模块完成这些职责即可。暂不需要微服务、消息队列、插件市场、中心数据库或自写通用力场语言。需要第二引擎时，再将已经出现的共同编译/运行行为整理成小型接口。

### 6.5 最小数据交接约定

以下约定先落实到普通数据结构和文件，不要求建立六套继承体系或通用中间语言：

| 交接点 | 必须交付 | 接收方不能自行猜测的内容 |
|---|---|---|
| 配置解析 → 构建 | 固定版本的组分/模型、明确数量、单位、几何规则、种子 | 质子化、母体力场、缺失参数、默认链长 |
| 构建 → 引擎 | 最终坐标/拓扑、实际组分清单、盒矩阵、原子映射、文件哈希和检查结果 | 原子排列、溶剂数、模型之间的连接与交叉项 |
| 引擎 → 执行 | 阶段输入、参数列表、预期输出及完成条件 | 科研协议、失败后换用何种物理模型 |
| 执行 → 分析 | 轨迹分段、时间范围、拓扑/映射、输出能力及完成情况 | 时间连续性、缺失速度/力、未写出的原子 |
| 分析 → 报告 | 观察量名称/版本、单位、选择、样本范围、误差方法、质量状态 | 把缺数据填成零、把未评估写为通过 |

组分的化学类型与场景角色分开：同一种小分子可作为溶剂或添加剂，角色本身不改变化学身份。颗粒中心、界面法向、链/颗粒允许区域属于构建规则；固定原子、位置约束和接枝成键属于不同物理设置，不能用“放在这里”隐式代表“永远固定在这里”。

只支持已实现的几何与协议组合。第一轮采用已有案例的三维周期正交水盒，不先实现任意表面、空间区域或通用势函数转换。最终身份映射在装填、加水/加离子、排序后检查并冻结；构建前只确定化学原子标识与预期组成。

## 7. 场景与组分选择如何落地

### 7.1 配置必须表达什么

组成输入可选择数量、摩尔浓度、质量分数等方式，但必须明确分母和参考体积。不能同时独立固定所有组分数、盒体积、最终密度和最终浓度，造成过约束。

以摩尔浓度为例，目标粒子数为：

\[
N_i \approx c_i N_A V_{\mathrm{L}}.
\]

整数化后应输出实际浓度与目标偏差；若偏差超过预设容差，则增大体系或改变构建约束。NPT 下最终体积会变，应报告基于平衡体积得到的实际浓度。带电体系还需同时满足电中性及盐配方约束；中和反离子与额外添加的盐分别计数。

聚合物质量分数必须使用包含端基、实际链长和电离状态的链质量，并声明反离子是否计入相应质量定义。纳米颗粒体积分数也需说明有效体积如何定义，不能与原子占据体积混为一谈。

### 7.2 多组分配置示例

以下 YAML 仅用于展示未来格式。PEO、二氧化硅和乙醇是说明性例子，不代表已选定首批科研体系。`candidate` 模型均未登记或批准，因此本示例应被验证器明确阻止进入正式生产。

```yaml
schema_version: 1
experiment:
  id: polymer_particle_additive_demo
  question: 聚合物与小分子在纳米颗粒表面的竞争接触

scenario:
  kind: multicomponent_solution
  resolution: all_atom
  boundary: periodic_3d
  box:
    shape: orthorhombic
    lengths_nm: [10.0, 10.0, 10.0]
  composition_basis: molecule_counts

components:
  - id: polymer
    chemical_ref: peo_ho_h_capped_dp20@candidate
    model_ref: peo_aa@candidate
    count: 4
  - id: particle
    chemical_ref: hydroxylated_silica_d4nm@candidate
    model_ref: silica_surface@candidate
    count: 1
  - id: additive
    chemical_ref: ethanol_neutral@candidate
    model_ref: ethanol_aa@candidate
    count: 20
  - id: solvent
    chemical_ref: water@candidate
    model_ref: water_for_selected_family@candidate
    count: 30000

model_assembly:
  compatibility_profile_ref: polymer_silica_ethanol_water@candidate
  required_status: validated
  charge_policy: require_explicit_neutral_composition

protocol:
  profile_ref: aqueous_particle_polymer@candidate
  temperature_K: 298.0
  pressure_bar: 1.0

replicates:
  - id: rep_001
    build_seed: 104729
    velocity_seed: 271828
  - id: rep_002
    build_seed: 130363
    velocity_seed: 314159
  - id: rep_003
    build_seed: 155921
    velocity_seed: 161803

analysis:
  profile_ref: competitive_surface_contacts@candidate
  groups:
    polymers: {component: polymer}
    nanoparticle: {component: particle}
    additives: {component: additive}
    solvent: {component: solvent}

  profile_ref: macos_cpu@candidate
  run_root: /absolute/path/to/simulation_runs
```

配置中的水数量仅是构建示例，不表示适合该混合物的平衡密度。表面电荷由引用模型给出；若不是中性，必须显式补充离子后才能通过检查。协议引用在正式使用时必须解析出每个阶段的步长、时长、控制算法和接受条件，不允许默认沿用现有 1 ns NVT/5 ns NPT。

上述重复定义是三个明确配对的实验，不是两组种子的笛卡尔积。每个重复生成独立 Run；采用相同构建而仅改变速度时，应记录共享初始构型，不能标作独立构建。

简单的小分子水化案例使用同一套 schema，只包含小分子与水，引用自己的已验证模型和协议；单链、多链和复杂体系不各自发明不同的运行程序。

### 7.3 CLI 与后续图形界面

拟议命令以同一个 Python 包入口提供；以下命令当前不可执行：

```text
python -m materials_sim doctor
python -m materials_sim catalog
python -m materials_sim validate experiment.yaml
python -m materials_sim build experiment.yaml --replicate-id rep_001 --run-root <root>
python -m materials_sim run --run-dir <run-directory>
python -m materials_sim status --run-dir <run-directory>
python -m materials_sim resume --run-dir <run-directory>
python -m materials_sim analyze --run-dir <run-directory>
python -m materials_sim report --run-dir <run-directory>
```

`doctor` 输出机器实际可用的工具、版本与功能。`validate` 在运行前给出模型覆盖、组分数、净电荷、预计粒子数、资源需求和缺少的验证项。构建后展示一份组分清单及三维快照，供检查表面、链连接和装填是否符合研究意图。

后续图形界面采用“选择研究问题 → 选择场景 → 添加组分 → 设置组成和环境 → 查看构建与验证结果 → 运行/分析”的流程。所有选择保存为同一份配置；界面不直接拼接引擎命令。

`validate` 仅进行静态检查和资源估计，不启动模拟或参数化。`build` 在唯一的新 Run 目录中快照输入、构建并返回其绝对路径；已有目录不覆盖。后续命令显式使用 `--run-dir`，不依赖全局数据库猜测 Run 编号所在位置。`status` 为只读查询。批量展开所有重复和集群任务不是最小框架的必需功能。

### 7.4 配置解析、单位和可移植性

1. **严格解析**：拒绝重复键、未知字段、未知 schema 版本、非有限数、非整数计数和重复组分/重复实验 ID；不得静默忽略拼错的科学参数。载入配置不执行脚本或任意对象构造。
2. **覆盖顺序**：版本化协议提供允许覆盖的默认值，实验文件仅覆盖白名单科研参数；命令行第一轮只覆盖执行位置和资源，不提供任意科研字段覆写。解析结果保留最终值及来源。
3. **单位边界**：核心结构坐标约定为 nm、时间为 ps，配置中其他带单位字段在入口显式转换；引擎和分析库的单位转换只在各自边界完成。任何无单位外部坐标必须由导入说明给出单位。单位测试覆盖 nm/Å、ps/ns、浓度体积和质量分数定义。
4. **相对路径**：科学资产路径相对于定义它的配置文件解析，不相对于启动命令的工作目录。可移植实验文件不保存某台机器的工具路径；第 7.2 节 `execution` 是本地执行示例，移动平台时另行绑定并记录。
5. **内容与位置分离**：科学 spec 哈希包含模型、协议、组成和种子等内容；本机路径和资源分配记录在执行元数据中。移动完整 Run 不修改科学身份；换硬件也必须新增 attempt 记录并重新检查可执行能力。
6. **演进规则**：旧版配置由显式迁移生成新文件，不原地改写历史 spec。暂不支持的模型、场景、空间约束或版本明确失败，不保存后假装生效。

第一轮只实现已参数化小分子的明确数量与现有加水路径；加水路径必须记录实际水数和最终盒子。摩尔浓度/质量分数求解、任意聚合物表达和自定义表面布局属于后续能力，不因 schema 能存一个字符串就宣称支持。

## 8. 组分库、模型库和身份映射

### 8.1 最小组分卡

小分子卡记录来源、结构、立体化学、质子化、电荷和原子映射。聚合物卡另外记录单元结构、连接规则、序列、端基、链长分布、分支和立构。颗粒卡记录晶体来源、几何、表面处理和原子分类。

模型卡记录力场名称及版本、精确参数文件、哈希、引用和许可、分辨率、支持元素、非键合约定、单点验证和目标物性验证。模型状态采用 `draft / parameterized / numerically_checked / validated / rejected / deprecated`，并带适用条件；“validated”不是对所有体系的永久批准。

### 8.2 原子与分子身份

需要贯通保存：

```text
component_id → molecule_id → chain_id / particle_id
             → residue_index → atom_uid → engine_atom_index
```

GRO/PDB 中的显示编号不能作为唯一身份；大体系中的编号限制、格式转换和重排可能造成混淆。每次构建/导出保存明确映射，分析选择以组分和映射为基础，不依赖 `resname ZIL`、`CAT` 等少数名称。

共价接枝改变了分子连接图，需要重新生成受影响的键、角、二面角和排除项，并更新身份映射。只把链的一端放在颗粒表面，不等于建立了共价接枝。

### 8.3 参数缓存与复用

参数缓存键至少包括化学图、质子化/电荷、立构、端基、连接模式、力场版本、参数化方法和工具版本。几何构建缓存另外包含链序列、几何约束和构建种子。构象相关电荷流程还应记录所用构象集合。

资产重用时校验内容哈希；模型许可与再分发权限写入卡片，不把网上下载得到的文件默认当作可自由发布的参数库。

### 8.4 输入快照必须包含实际依赖

现有 [ZIL 系统拓扑](../../zwitterion_hydration_md/topology/system.top) 除了引用本地 `zil.itp`，还引用 `amber14sb.ff/forcefield.itp` 和 `amber14sb.ff/tip3p.itp`。因此，仅冻结项目目录中的几个 `.top/.itp` 文件不足以证明两台机器读取了相同参数。

每个阶段应记录实际包含的力场文件、条件宏、包含路径、位置约束参考坐标、索引和其他辅助输入；同时保存原始模板、生成后最终输入及哈希。GROMACS 预处理器会解析 include 和宏，`-pp` 可输出预处理拓扑，`-po` 可输出处理后的 MDP；应将它们与 `.tpr` 一并保存。[GROMACS grompp 官方说明](https://manual.gromacs.org/current/onlinehelp/gmx-grompp.html)。[^25]

预处理输出不能代替原始来源和许可记录。Run 应包含重建所需输入，或引用可离线定位、按哈希固定的资产包；不可依赖指向旧课题目录的可变符号链接。第一轮只处理现有案例已知的依赖和宏，不编写自己的通用 GROMACS 预处理器；无法确定的依赖应阻止构建。

## 9. 协议、质量检查与续跑

### 9.1 不使用一个通用平衡模板

| 场景 | 协议需要重点处理的内容 |
|---|---|
| 小分子稀溶液 | 溶剂松弛、温压稳定、溶质构象与有限尺寸 |
| 聚合物单链溶液 | 初始链形态、链尺寸、构象记忆、盒中自相互作用 |
| 聚合物浓溶液/熔体 | 装填高能接触、密度调整、链松弛和缠结 |
| 颗粒混合溶液 | 表面处理、核心/表面约束、吸附动力学与粒子间距 |
| 表面/薄膜/刷层 | 压强耦合方向、非均匀几何、长程静电处理 |
| 粗粒化体系 | 该模型规定的非键合设置、步长与平衡办法 |

GROMACS 的边界、墙面、长程静电和压强耦合设置具有不同适用条件；表面/真空层体系不能直接复制三维均匀液体的 NPT 参数。[GROMACS MDP 选项](https://manual.gromacs.org/current/user-guide/mdp-options.html)。[^20]

每个协议固定函数和默认设置，同时允许有边界的参数输入。任何覆盖配置都记录到解析后的 spec。高温退火、软势、约束释放等只在有依据的协议中出现；其轨迹标为平衡/构建数据。

### 9.2 四级验收

1. **化学与输入验收**：价态、连接、组成、电荷、参数覆盖、文件身份一致。
2. **数值验收**：拓扑预处理、能量/力转换一致性、最小化及短动力学无数值崩溃。
3. **采样验收**：慢观察量、相关性、构型重复和统计误差满足预定义标准。
4. **物性验收**：与适当的文献、实验或独立模型证据比较，标明适用范围。

`grompp -maxwarn 0` 可以作为基础硬检查，但不是物理可靠性的充分条件。未通过采样验收的运行也可保留用于诊断，其报告必须显示 `insufficient_sampling`。

### 9.3 运行状态与断点续跑

```text
DRAFT → PREFLIGHT_PASSED → BUILT → EQUILIBRATING → SAMPLING
                                             ↓
                                    FINISHED → QC_EVALUATED

活动阶段可进入：INTERRUPTED / FAILED
科学质量另行记录：not_evaluated / accepted / insufficient_sampling / rejected
```

不能仅凭 `.gro`、`.tpr` 存在或进程退出码为零判断目标时长完成。需要核对阶段清单、预期/实际步数、检查点时间、日志终止信息和结果完整性。每个阶段设置单写者锁，避免两个进程同时续跑；每次 attempt 记录命令、工作目录、环境和返回状态。

续跑前校验输入、拓扑、协议和检查点对应关系。输入不一致时失败并报告原因。GROMACS 的检查点保存恢复需要的状态，并对追加输出做校验；修改或丢失历史输出可能导致追加失败。跨硬件执行也不能承诺逐位相同轨迹。[GROMACS 长模拟管理](https://manual.gromacs.org/current/user-guide/managing-simulations.html)。[^21]

旧 ZIL runner 的输入快照中 `system.top` 会在加水时被修改。新核心应分别保存原始不可变模板和构建后的最终拓扑，分别计算哈希，避免“输入清单哈希”和实际使用文件含义不一致。

### 9.4 不混淆预检、模型验证和研究质量

`PREFLIGHT_PASSED` 只说明当前用途的运行前检查通过，不代表新材料物性已验证。模型卡状态、组合包适用范围、Run 执行状态和各质量检查结果分别保存；尚未做的检查是 `not_evaluated`，不能默认通过。

必须保留一条受约束的模型验证路径，否则“所有模型必须先 validated 才能运行”会导致新模型永远无法获得验证数据：

- **工程小量测试**：复用明确来源的参数，使用独立短协议；输出只能证明编排和数值链路，不能继承原正式长协议的采样结论。
- **模型验证实验**：参数覆盖、拓扑及可执行的硬检查通过后，可运行预先定义的验证协议，产出对照证据；不因运行完成自动升级模型卡。
- **正式研究**：要求模型及组合包具有对应条件/目标量的验证记录，采样是否充分仍由本次 Run 的证据判断。

三者不是绕过参数检查的开关；缺失参数、未知交叉项、结构错误在所有路径都必须失败。升级模型状态时记录具体证据、适用范围和版本，修改参数后不能沿用旧参数哈希对应的批准结论。

同一 Run 内中断后按未变协议恢复，新增 attempt；改变体系、协议或延长原已完成目标则创建带父记录的新 Run，并明确是否使用父检查点续接。无有效检查点时，应从已冻结的阶段起点创建新 attempt 并保留失败输出，不向残留文件盲目追加。物理阶段已完成而分析失败时，只重试分析。

状态文件采用原子更新；进程终止、超时和磁盘耗尽不能先写为成功。恢复遗留锁前核实进程/主机与 attempt，不能只按锁文件年龄删除。第一轮只承诺本地单机单写者；网络共享目录及跨节点锁留待集群阶段验证。

## 10. 分析能力升级

### 10.1 观察量按场景配置

| 类别 | 首批观察量 | 解释要求 |
|---|---|---|
| 通用数值质量 | 温度、密度、压力、能量、实际模拟时间 | 分阶段统计，不能把瞬时压力波动简单判为失败 |
| 小分子/水化 | RDF、去重水数、氢键、接触和驻留 | 固定选择和计数定义；驻留需要合适输出频率 |
| 聚合物构象 | 回转半径、端到端距离、链间接触、构象分布 | 按链统计，先处理周期边界和连接 |
| 聚合物溶液 | 聚集尺寸、浓度分布、溶剂化、扩散 | 判断慢松弛；区分溶质富集与全局相分离 |
| 纳米界面 | 表面法向/径向密度、接触覆盖、吸附层结构 | 归一化考虑几何可达体积和表面积 |
| 混合体系 | 竞争接触、桥连比例、颗粒间聚集和组分富集 | 包含二元/三元对照，不把所有变化归因于一个因素 |

回转半径示意为：

\[
R_g^2 = \frac{\sum_i m_i |\mathbf r_i-\mathbf r_{\rm COM}|^2}{\sum_i m_i}.
\]

链必须先按连接关系跨周期重建，否则断开的显示坐标会产生错误链尺寸。扩散分析还需要连续的解包裹坐标；MDAnalysis 的 `NoJump` 文档特别要求顺序处理并注意帧间位移条件。[MDAnalysis NoJump](https://docs.mdanalysis.org/2.10.0/documentation_pages/transformations/nojump.html)。[^22]

单分子水化数、每条聚合物链的水化数、每个重复单元的水化数，以及颗粒单位表面积的接触数必须使用不同字段。跨多个溶质取水分子并集与“每个溶质分别计数再求平均”是不同统计量，需由协议明确选择。

大型体系分析采用逐帧流式输出与邻域搜索，避免存放所有原子对距离与全部帧结果。读取 GRO/XTC 时保存可重建链连接和质量的辅助拓扑；不能因 GRO 能读入就认为所有链分析所需元数据都齐全。

### 10.2 收敛与不确定度

密度平稳不能证明聚合物链已松弛，也不能证明吸附/解吸已充分采样。每个实验应预先选慢观察量，检查时间分块、相关时间、不同构建与速度种子的结果，并报告有效样本量或其无法可靠估计的原因。

建议首批科研基准从三个独立构建/速度组合开始，再根据观察量调整重复和时长；“三个重复”是工程起点，不是通用充分条件。单链多个副本在同一盒中存在相关性，不能自动当作独立实验。文献建议将相关性和独立初始条件纳入统计评估。[Grossfield 等的不确定度与采样实践](https://pmc.ncbi.nlm.nih.gov/articles/PMC6286151/)。[^23]

对于没有观察到足够吸附/解吸转换的轨迹，应报告采样不足或受初态约束；不能只给一个很小的时间块 SEM 就称为可靠平衡结论。

### 10.3 与机器学习的连接

模拟结果可形成单独的物性数据表，至少带：体系哈希、模型版本、协议版本、组分组成、实际温压、观察量定义、重复数、误差、质量状态和来源 Run。

模型预测、MD 估计、真实实验测量分别标记来源；不同分辨率和力场生成的同名字段不自动合并。当前 Nature 六单体模型保留自己的输入域，不能直接用于新聚合物/纳米体系的结论。

### 10.4 分析需求必须在开跑前反向检查

每个分析定义应声明需要哪些原子、连接、质量、电荷、坐标/速度/力、时间间隔和轨迹精度。配置解析时将这些要求与协议输出比对；运行结束后再核对实际文件，不只检查预期文件名。

GROMACS 的压缩坐标输出间隔、精度和原子组分别受 MDP 设置控制；输出字段不足时不能靠事后分析补回来。[GROMACS 输出参数](https://manual.gromacs.org/current/user-guide/mdp-options.html)。[^20] 例如只写溶质坐标便不能计算水化数；稀疏轨迹也不能直接支持短时驻留过程。第一轮至少保证现有水化分析需要的水和溶质、盒子、时间及映射完整。

报告应保存分析版本、选择、截断距离及单位、起止时间、去平衡段方法、采样步幅和轨迹分段清单。续跑交界的重复时间帧、时间回退或缺段要检测；不得把不连续片段当作连续动力学，缺数据应明确标记，不补零或随意插值。原始轨迹不在分析过程中就地重写。

## 11. macOS/Linux 环境与计算资源

### 11.1 软件环境策略

历史 ML 的 Python 3.9 环境继续保持。新模拟核心单独建立环境，建议以 Python 3.11 作为初始兼容性验证候选，最终版本由选定工具的共同支持范围和实机测试决定，不能先承诺一份锁文件覆盖所有工具。

Python 3.9 的历史 ML 约束由 `hydrogel_ml_run/AGENTS.md` 管理；根规则与 `materials_simulation/AGENTS.md` 管理公共环境和新平台边界。3.11 仍只是待确认的设计候选，不是已获准的环境变更。第一轮优先评估现有环境能否支持最小核心；若确需新版本，先明确环境变更范围，再单独建环境，不修改历史 ML 解释器。治理文件及项目内技能的建立不表示运行框架已经实现。

至少区分：核心与分析环境、Amber 参数化环境，以及后续需要的聚合物/材料或量化环境。通过明确可执行路径和任务清单调用，避免把所有包装进一个巨型环境。

按 `osx-arm64`、`linux-64` 分别生成并验证锁文件；Linux ARM 或 Intel Mac 只在实际测试后列为支持。虚拟环境、Homebrew 二进制和 CUDA 库不跨系统复制。复杂参数化工具若在 Mac 上暂未打通，可由原生 Linux 参数化任务完成并返回已哈希的模型资产，不回退到 Windows。

### 11.2 执行配置

| 执行配置 | 主要职责 | 验证要求 |
|---|---|---|
| macOS CPU | 开发、构建、小体系与短程验证 | 当前原生 GROMACS 为 CPU 构建；新场景仍需验证 |
| macOS GPU（可选） | 经验证的小中型生产任务 | 另行构建、验证数值与实测性能 |
| Linux CPU | 自动测试、参数化、小规模计算 | 与锁定输入一致的端到端测试 |
| Linux GPU | 大体系、长轨迹、重复与批量任务 | 驱动、引擎、参数能力和性能记录 |
| Linux 调度集群 | 多任务、检查点与资源配额 | 后续加入 Slurm 等执行配置，提交脚本只负责调度 |

GROMACS 当前安装文档列出 Apple M 系列的 OpenCL 路线，同时注明 OpenCL 已弃用；NVIDIA 推荐 CUDA。因此不能说“Mac 不能用 GPU”，也不应把项目长期算力计划建立在尚未验收的 Apple GPU 构建上。[GROMACS 安装指南](https://manual.gromacs.org/current/install-guide/index.html)。[^24]

### 11.3 规模与成本预估

下面是按水密度约 1 g/cm³、每个水分子三个原子估算的纯水盒粒子数量，不是性能基准，也没有计入溶质：

| 立方盒边长 | 约水分子数 | 约原子数 |
|---|---:|---:|
| 5 nm | 4,180 | 12,500 |
| 10 nm | 33,400 | 100,000 |
| 20 nm | 267,000 | 802,000 |
| 50 nm | 4,180,000 | 12,500,000 |

用 2 fs 步长计算 100 ns，需要约 5,000 万步；这只适用于采用该步长的模型。大纳米颗粒加足够溶剂层可能迅速进入百万到千万原子级，不能将实验颗粒尺寸直接映射为默认 Mac 任务。

正式提交前对实际体系做短性能测试，并按相同硬件、并行设置和模型估算：

\[
T_{\rm wall,days} \approx
\frac{n_{\rm replicas}\,t_{\rm simulated,ns}}{v_{\rm measured,ns/day}}
\]

该式表示串行等效总耗时；并发墙钟时间还取决于资源配额。平衡、构建和分析另计。磁盘按实际输出频率和短样本大小外推，资源不足时明确阻止提交，不自动缩短研究协议。

## 12. 分阶段实施与交付标准

以下是工作分解与工程估算，不是科学计算时长承诺。估算按一名熟悉 Python/MD 的开发者推进、已有可用参数为条件；参数研究、长时间采样和外部硬件等待单独计算。

| 阶段 | 交付内容 | 退出标准 | 工程量级 |
|---|---|---|---|
| P0：基线与资产审计 | 文件清单、哈希、历史归属、环境记录、模型覆盖表 | 明确哪些可重现、哪些缺原始运行文件；不会丢失科研输入 | 2–4 个工作日 |
| P1：通用小分子核心 | 分 P1a 最小框架、P1b 第二案例与混合装填扩展 | P1a 按第 12.3 节；完整 P1 还需两个历史案例输入对照、一个新增多小分子案例和 Mac/Linux 端到端验证 | 原 1–2 周仅作初估，P0 后按依赖、资产缺口及验收矩阵重新估算 |
| P2：聚合物与混合溶液 | 一个聚合物家族、polyply/PACKMOL、链映射、构象分析 | 单链 → 多链 → 加小分子逐级通过；明确参数适用范围 | 2–4 周，另加模型验证 |
| P3：纳米材料集成 | 一种纳米材料、表面模型、兼容组合、空间装填与界面分析 | 纳米/水、纳米/小分子、纳米/聚合物对照后再验证完整混合体系 | 3–6 周，强依赖参数可得性 |
| P4：尺度与执行扩展 | 按需增加 LAMMPS、Martini、Linux 集群批量运行 | 每条新增路线有独立基准和阻止错误组合的测试 | 每条路线单独估算 |
| P5：场景选择界面 | 组分选择、配置生成、三维预览、运行与报告入口 | 界面与 CLI 生成相同 spec，不出现另一套科研逻辑 | 核心稳定后约 1–2 周 |

LAMMPS 如果被 P3 的材料模型所必需，应在 P3 内实施，不能拖到 P4 再声称该材料已支持。反过来，如果首个颗粒的验证组合已被 GROMACS 完整支持，就暂不增加 LAMMPS 维护负担。

一个真正包含聚合物、小分子和一种纳米材料的可信平台，至少需要完成 P0–P3。只完成 P1 或增加配置选项不能宣称已实现最终目标。

### 12.1 第一阶段具体改动清单

本清单覆盖完整 P1 及迁移收尾，不要求在“先搭框架”的 P1a 中一次完成；近期最小范围以第 12.3 节为准。

1. 新建 `materials_simulation/`，建立包、测试和最小 schema；固定支持 macOS/Linux。
2. 将当前两套 GROMACS 调用、哈希、运行清单和阶段执行逻辑收敛到共享核心。
3. 把 ZIL 的盒子、构象、阶段长度等转为基准案例配置；现有科学输入保持逐文件哈希一致。
4. 将离子对正式流程引用的 EM/NVT/NPT 作为正式输入资产明确登记；核对内容后调整引用，不改 MDP 数值。
5. 检查离子对冻结初始溶剂化坐标的实际可得性；当前需要外部传入，不能用新生成水盒冒充历史初始条件。
6. 将分析脚本整理成可导入的包内模块，补全组分身份与单位约定，解决运行目录对 import 的影响。
7. 增加完整状态检查、错误组合拒绝、改参数后拒绝续跑、输入被改写检测。
8. 新增可追溯的原生 Mac/Linux 验证记录；不覆盖旧 Windows 验收文件。
9. 更新工作区与各案例 README，明确历史正式结果、新平台验证状态及运行命令。
10. 只有迁移验证通过后，才归档旧生产入口，保留迁移映射和原文件快照。

### 12.2 首批基准案例

| 基准 | 目的 | 特别要求 |
|---|---|---|
| 现有 ZIL + 水 | 保持已有小分子水化链路 | 输入/参数哈希对照，原子顺序与分析计数一致 |
| 现有 CAT/ANI + 水 | 保持多分子身份、带电组分与总体中性 | 缺冻结坐标时标注阻塞，不替造 |
| 两种已验证小分子 + 水 | 验证通用组分数和装填 | 选具体兼容模型后登记 |
| 中性线性聚合物单链 + 水 | 验证连接、端基和链分析 | 建议从 PEO/PEG 候选开始；具体参数另行批准 |
| 同一聚合物多链 + 水 + 小分子 | 验证组分映射和跨组分作用 | 保存独立构建与速度种子 |
| 指定纳米材料 + 水 | 验证表面和水界面 | 化学状态及母体力场明确 |
| 聚合物 + 纳米材料 + 小分子 + 水 | 验证最终集成场景 | 先完成二元对照和整体参数检查 |

聚合物阶段应尽量让首批小分子、水和聚合物处于同一套已验证母体力场；不能因为旧案例是 GAFF2 就强制所有新聚合物和纳米材料沿用 GAFF2。

### 12.3 近期交付：P1a 最小可运行框架

**2026-09-14 实施更新**：P0 源哈希基线核对和 P1a 的 Mac CPU 工程闭环已完成。实际交付采用 JSON + 标准库核心、可导入包与 `python -m` 入口，未安装新依赖；未创建大型长期目录树或发行包。现有 ZIL + 2,957 水、8,910 原子的 EM/NVT/NPT/短采样、640→1,000 步 NVT 检查点续跑、跨目录输入隔离以及 21 帧新旧计数对照均有实测证据；新框架 22 项测试和旧分析核心 5 项测试通过。Linux、CAT/ANI 共用核心、硬杀/断电及父 Run 派生等仍待后续工作，整体升级未完成。详见 [Mac 框架验收记录](../../materials_simulation/docs/2026-09-14__mac-framework-acceptance.md)，不能由短轨迹宣称体系已平衡。

**目标**：不改变已有科研参数和旧入口，以现有 ZIL + 水案例验证新核心能够独立完成一个短程闭环。首轮不同时实现聚合物和纳米材料。

| 首轮做 | 首轮不做 |
|---|---|
| 一个可安装/导入的 Python 包及 `python -m` 入口 | 空插件、通用工厂、六类对象的大型继承体系 |
| 明确数量/既有加水规则、固定版本资产、单位与错误提示 | 自动浓度求解、任意材料自动参数化 |
| GROMACS 单引擎、本地 CPU、显式 Run 目录 | LAMMPS、Martini、GPU 优化、Slurm 和 Web 界面 |
| 不可变输入、构建输出、阶段状态、检查点与 attempt | 批量调度、自动选择科学模型、自动删除运行数据 |
| 一个小分子案例、基础质量摘要和水化计数 | 吸附自由能、聚合物物性或新纳米模型科学验收 |

代码可以先以少量按职责划分的模块实现配置、资产快照、GROMACS 构建/运行、状态和分析；模块变大时再拆为第 6.3 节中的子包。不要先创建一排空目录、`pass` 或未实现命令来显示“架构已搭好”。

最小实施顺序：

1. **基线**：只读清点 ZIL 案例的实际依赖、原子/组分数和原分析定义，保存源文件哈希；明确新 Run 位置。
2. **配置与构建**：实现一个真实可解析的案例配置和静态检查，导入既有模型、加水并生成最终拓扑/映射。构建产物不能引用可变旧目录才能运行。
3. **数值闭环**：编译并执行 EM、短 NVT、短 NPT、短采样，保存实际步数和输出；例如动力学各段采用 500–2,000 步的工程测试起点，具体值先核对现有约束和步长。短协议另存为工程测试版本，不修改原 MDP，也不宣称已经平衡。
4. **状态与恢复**：至少真实测试一个动力学阶段中断、检查点恢复和完成识别；再测试输入改变后拒绝恢复。
5. **分析与交付**：对短轨迹输出水化计数与基础数值摘要，保留明确的 `not_evaluated`/采样限制；形成可直接复跑的最短使用说明。

如果现有 runner 无法在不改变旧文件的前提下提供该闭环，应将必要行为提取到新包，并用同一冻结输入对照；不能仅在新 CLI 中转调硬编码旧课题路径就声称完成通用化。

**首轮验收表：每项必须提供证据或注明未通过，不以目录存在作为完成标准。**

| 验收项 | 通过条件 |
|---|---|
| 配置 | 正例可解析；未知字段/模型、错误计数/单位、未支持场景明确失败 |
| 无隐式执行 | `doctor`、`validate`、`status` 不开始模拟，不改原科研输入 |
| 输入隔离 | 原文件哈希前后一致；快照完整；旧目录不可用时新 Run 仍可找到其必要输入 |
| 身份与构建 | 实际组分数、原子排列、总电荷、盒子和拓扑一致；水数可追溯 |
| 真实运行 | 真实 GROMACS 完成指定阶段目标，含短动力学；只通过最小化不算完整闭环 |
| 续跑与失败 | 有真实中断/恢复证据；输入改变、残留输出和重复启动不能被当作正常完成 |
| 分析 | 同一段固定轨迹的新旧水化计数一致；人工小例验证去重、周期距离和单位 |
| 路径可移植 | 从不同工作目录、含空格/中文的测试路径执行不改变输入解析；Run 搬移后仍可定位自身资产 |
| 平台标签 | macOS 与 Linux 分别记录实测结果；缺 Linux 机器时只能交付“Mac 框架验收，Linux 待验收” |

P1a 通过后，P1b 再加入 CAT/ANI 与新增多小分子案例，检验是否仍存在 ZIL 专用假设。两个案例未能共享同一套核心前，不提前开展全部聚合物构建。未知纳米材料类型不阻塞 P1a，但仍阻塞对应模型分支的正式选定。

### 12.4 资产保留与发布范围

源码、测试和小型版本化配置进入新平台的版本管理范围；轨迹、检查点、日志和大体积构建结果留在明确的 Run 存储位置。建立 Git 仓库、归档旧目录、迁出无关项目和清理缓存均是实施时单独明确的操作，不是搭框架的隐含动作。

Run 报告应列出“重建体系”“断点续跑”“重新分析”各需要保留的文件。检查点本身不能代替分析轨迹；只有报告而无输入也不是完整复现包。未制定保留清单、校验副本并获得清理授权前，不自动删除任何历史 Run 或旧科研数据。

## 13. 验证、迁移和回滚策略

### 13.1 工程验证

- Schema：负数、缺单位、浓度过约束、无效连接、未知模型版本应明确失败。
- 化学构建：单元数、原子数、端基、价态、净电荷和序列满足定义。
- 拓扑：原子顺序、质量、电荷、函数形式、排除与特殊配对正确；缺交叉参数时拒绝。
- 数值转换：同一小体系在转换前后比较能量和力；不同函数项分组时使用事先声明的映射。
- 状态：中断、磁盘不足、部分输出、重复启动、恢复与输入变化都有测试。
- 分析：人工已知答案验证周期距离、链重建、并集计数、归一化与单位。
- 平台：同一锁定输入在 macOS 和 Linux 上测试；不以两台机器的轨迹逐字节相等作为成功标准。

每个场景发布前至少有一个真实短程端到端测试，不只使用 mock。针对昂贵体系，快速测试用于编排和稳定性，长程采样验证作为独立证据。

### 13.2 科学验证

新聚合物用适合其体系的密度、链尺寸/构象和必要的参考数据校验；界面模型选择与目标相关的表面、水界面或吸附证据。每项容差在模型卡中给出来源或工程理由，不设置“一切误差小于 5%”式的统一标准。

大体系从纯组分到二元、三元再到全体系逐层构建证据。中间对照用于定位问题，但不把二元验证宣称为整个多元相图的验证。

### 13.3 迁移和回滚

实施前创建只读基线和哈希清单；迁移先复制到新位置并更新引用，验证完成前保留原目录。历史报告和原始参数不批量替换路径文字，新平台用迁移映射连接旧位置与新资产身份。

旧环境留在原路径直至替代环境验证通过。新环境按平台重建，记录精确工具路径，不直接搬移虚拟环境后继续使用。回滚通过切回旧入口和基线输入实现，不覆盖新平台生成的独立 Run。

## 14. 尚需明确但不妨碍核心建设的选择

- 第一种聚合物：化学结构、端基、聚合度/分布、共聚序列、电离度与立构要求。
- 第一种纳米材料：氧化物/黏土、金属或碳材料；具体尺寸、表面处理和目标温度。
- 最优先的科学问题：局部水化、竞争吸附、颗粒分散、聚集、溶胀或材料物性。
- Linux 计算资源：CPU/GPU、内存、存储、调度方式；目前不指定必须购买的硬件。
- 可接受的首批模型覆盖：一个聚合物家族和一种纳米材料，或更广但需要更多专项验证。

在这些选择确定前，P0/P1 可以推进。P2/P3 的模型清单、力场分支和科学验收不能通过猜测补全。本文以 PEO/PEG 与二氧化硅作为易理解的示例，不构成具体研究体系或参数包的最终选定。
