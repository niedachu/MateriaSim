# 多组分＋多场景：项目实施与分层验收方案

## 1. 决策摘要

以现有 `materials_simulation/` 为唯一新核心边界，保留可用的原生运行、冻结输入、日志和恢复机制，重构体系定义、模型组合、构建、协议与分析。不先搬迁整个项目，不删除旧课题，也不一次性创建长期目录树。

本次修订把原先以“小分子水溶液＋无水周期盒”为终点的近期方案，扩为有明确材料与验证边界的 M1—M6 主线：

```text
M1 核心契约、阶段与历史读取
 → M2 已有 ZIL / CAT / ANI 资产共用核心
 → M3 真正多组分液体与选定混合溶剂
 → M4 一个聚合物家族：链、溶液、熔体
 → M5 一种真实固相与 LAMMPS
 → M6 表面/颗粒、固液界面与复杂组合
```

M4、M5 在 M1—M3 的交接约定稳定后可分别推进；不要求先完成所有聚合物研究才能做固相。M6 必须具有选定材料的内部与跨组分模型证据，不能仅靠前两条路线各自跑通。

交付分两级：M1—M3 形成限定模型范围的小分子实用版本；M4—M6 贯通选定聚合物、固相和界面，才达到本次扩展主线的工程目标。两者都不等于任意材料的科学验证完成。无水周期盒保留为去水依赖回归，不能代表固体或真空支持。

修订 2 仅获文档授权；随后用户授权开始执行，已落实 M1、M2 与受限工程验收，当时未安装依赖。修订 5 对应用户继续授权安装原生 Packmol 和推进已有模型装配，完成 M3a 的已有模型子集；没有清理旧文件、改 ML 环境、下载新模型或启动正式长模拟。已实现接口以模块 README 为准，后续阶段与本文复杂体系配置仍是设计。

- 37 项测试通过；两个真实 ZIL 短程 Run 通过，其中包含预算中断/原检查点恢复、变更拒绝、非 prod 中间阶段分析、非零时间/步数原点。旧轨迹 21 帧计数一致，149 个历史文件及清单保持不变。
- M2 已完成当前 macOS CPU 子集：ZIL＋水与预建 CAT/ANI＋水使用同一核心，45 项测试通过；各完成 8 ps、恢复保护与各 21 帧算法对照通过。同一新 Mac 固定帧下旧/新拓扑的能量/力迁移比较通过，88 个指定旧资产文件保持不变。详见 [M2 记录](../../docs/validation/2026-09-14__m2-core-reuse-acceptance.md)。
- M3a 已有模型子集通过：原生 Packmol 21.2.3；ZIL×2＋水、CAT×2＋ANI×2＋水、ZIL＋CAT＋ANI＋水、ZIL×2 无水周期盒，整数计数、区域/实例映射和参数合并；66 项测试通过，四例真实短程与独立逐帧接触分析通过，含三组分真实中断/恢复及隔离负例。见 [M3 子集记录](../../docs/validation/2026-09-14__m3-packing-subset-acceptance.md)。

- 证据与具体限制见 [M1 验收记录](../../docs/validation/2026-09-14__m1-core-acceptance.md)。运行数据在独立临时工程目录，未作为长期科研归档。

## 3. 支持范围与完成口径

### 3.1 四个维度，不是任意选项的笛卡尔积

- 材料身份：小分子、离子、合成聚合物、生物大分子、无机材料。
- 结构与场景：均相或分区液体、链、熔体、晶体、玻璃/非晶、表面、有限颗粒和界面。
- 物理模型：分辨率、相互作用形式、参数、交叉作用及数值实现约束。
- 研究任务：构象、混合、扩散、结构稳定性、吸附、力学/热学等具体观察量。

纳米尺度是几何和形貌信息，不是通用参数类型；有机晶体也不能只按“固体”就自动选金属势。相态标签记录制备目标和观察结果，不能因为配置写了 solid 就判定模拟为固体。

### 3.2 材料能力矩阵（M2 已验收；M3 部分实现，M4—M6 待实施）

| 场景 | 明确交付范围 | 阶段 | 发布限制 |
|---|---|---|---|
| 既有单溶质/离子对水盒 | ZIL＋水、CAT/ANI＋水 | M2 Mac CPU 已验收 | 固定干态构型导入、新 Mac 单帧迁移检查；非旧 Windows 轨迹复现 |
| 多溶质水溶液 | 不同分子、同种多个副本，至少一个多种非溶剂组合 | M3 | 严格满足指定计数，模型包覆盖完整 |
| 混合溶剂液体 | 一组明确选定、参数完整的溶剂组合 | M3 | 整数数量先行；配比换算另有独立子项 |
| 周期无溶剂盒 | 已有中性分子短测 | M3 回归 | 不代表真实体相、固体或非周期真空 |
| 聚合物单链及多链溶液 | 一个选定家族，明确链长、端基、链数 | M4 | 不覆盖任意聚合物或生物大分子 |
| 聚合物/小分子溶液及熔体 | 该家族的非共价混合与多链体相 | M4 | 熔体须独立制备/平衡流程，不套稀溶液模板 |
| 聚合物玻璃态 | 指定热历史与冷却路径 | M4 扩展子项 | 不属于熔体验收的自动结果 |
| 晶体固相 | 一种选定晶体与完整势模型，包含 LAMMPS 实现 | M5 | 几何、单位、势和协议全部验收；不是所有固体 |
| 非晶无机固体 | 材料专属制备和结构基准 | M5 扩展子项 | 不能由晶体构建器推断已支持 |
| 固液界面、颗粒分散与复合体系 | 选定表面/颗粒、溶剂、小分子和聚合物逐级组合 | M6 | 各形貌单独验证，表面模型和交叉作用明确 |

M3 的最终液体交付包含选定混合溶剂，不再用“水相＋无水盒”替代。若其材料、依赖或验收未落实，只能发布已完成子集，不能标记 M3 整体完成。

非周期孤立体系、蛋白质/核酸、支化/接枝/交联网络、粗粒化、反应势、极化、恒电位和机器学习势按需要单独设任务。不创建空实现，不声称 M4 的线性聚合物同时覆盖这些路线。非周期边界不以大周期盒替代。

### 3.3 能力与证据状态

- 软件：未实现／已实现待验收／通过指定平台和后端工程验收。
- 模型：缺失或冲突／参数完整候选／在注明范围内有科学验证。
- Run 执行：准备、中断、完成、失败等操作状态。
- Run 质量：结构与参数、数值物理、采样与目标性质分别为未评估／通过／不通过，并链接证据。

能力记录的键包括组分模型组合、场景、协议、引擎及其支持版本、平台和验收等级。支持 A 和 B 不代表 A/B 混合通过。科学验证必须写明材料状态、温压/组成范围和观察量；不做全局“可信”勾选。

## 4. 核心契约与现有代码改造

### 4.1 数据职责与唯一信息来源

下列名称为拟议数据职责，不要求一项对应一个类、文件或服务。

| 对象 | 内容与职责 | 禁止混入 |
|---|---|---|
| Component | 化学身份、形式电荷（适用时）、结构或生成定义；聚合物连接/端基，固体晶型/表面 | 模拟步数、机器路径 |
| Model | 该组分的分辨率、模板、参数化规则/资产、映射、来源和适用范围 | 实验数量、固定平衡流程 |
| InteractionBundle | 全体系势模型、全局约定、交叉作用、多体覆盖、引擎约束和验证引用 | 用模型名字代替参数完整性 |
| SystemSpec / Scenario | 组成、实例组、区域、晶胞、周期方向、初始形貌、制备目标和构建方法 | 引擎进程操作 |
| Protocol | 有序阶段、状态交接、有效物理/数值设置、产物与完成条件 | ZIL/CAT 等名称分支 |
| Experiment | 问题、用途、上述引用、比较变量、分析需求、种子与重复设计 | 未经授权的计算和隐藏默认配方 |
| ExecutionProfile | 本机工具位置、资源、时间和存储预算 | 材料身份；资源差异仍须记录 |
| ResolvedSystem / StageArtifacts | 已构建体系、参数来源及阶段实际产物交接 | 只有文件名而无格式、身份、单位 |
| Run / AnalysisRun | 冻结输入、版本、attempt、执行与质量状态、原始及独立分析证据 | 原地改写材料卡和历史结果 |

组分模型与模型包都参与科学内容身份。模型包拥有相互作用语义；协议中的截断、长程算法、约束等数值选择必须满足模型包约定，不允许两个位置各自静默覆盖。解析后仅有一套完整有效设置。

### 4.2 依赖与交接

```text
CLI → 解析组件/模型包/体系/协议 → 能力和完整性检查
                  ↓
      参数化与专用构建步骤（按依赖排序）
                  ↓
      ResolvedSystem：结构、参数引用、身份、QC
                  ↓
      引擎输入生成与预处理 → 阶段执行/恢复
                  ↓
      StageArtifacts → 分析任务 → 分层验收

公共底层：文件与哈希、运行存储、锁、预算、来源与状态
```

参数化与几何构建不是强行固定为先坐标后参数；聚合物构建可能先需要连接参数或粒子尺寸。构建计划明确每步输入输出与依赖，首版只执行显式序列，不建立通用任务 DAG。

模型库不导入运行模块，分析不能反向启动 MD。构建记录先生成稳定身份映射，再由引擎预处理输出核对；不把 GROMACS 展开拓扑作为所有材料身份的唯一来源。

### 4.3 已解析体系的共同约定

- 记录粒子 UID、组分与实例组、引擎索引映射、坐标及模型必需属性；分子/链/残基 ID 只在适用结构中存在，不为金属晶体伪造分子。
- 坐标与晶胞采用显式单位。晶胞为三个基矢的 3×3 矩阵，约定基矢存为行；记录三方向周期性和原点。格式转换记录旋转/重排，不默认三斜盒等于三个盒长。
- 有键模型保留连接与局部身份，跨周期连接记录晶格位移；纯多体模型保留元素/类型及势映射，不要求虚构固定键或固定电荷。
- 虚拟位点、质量为零的位点等若尚未实现，应明确拒绝对应模型，不能用“所有粒子必须是有质量真实原子”描述永久通用契约。
- 记录实际组分数量、总质量、适用的电荷、区域归属、生成种子、参数资产与构建 QC。请求组成和实际组成分别保存。
- 首版只实现已选场景所需子集；可以表达某项信息不代表构建器、引擎和分析器已支持该项。
- 不强制把多体势翻译成成对分子拓扑。共同层保存模型语义和原生资产引用；引擎专有项必须声明，不可静默丢弃。

GMSO / Interchange 作为分子参数表示和转换的评估对象；先用小基准确认语义覆盖、原子顺序、单位和同坐标能量/力，再决定接入。不以“能导出文件”证明跨引擎物理等价。[GMSO 官方设计](https://github.com/mosdef-hub/gmso)、[Interchange 参数映射](https://docs.openforcefield.org/projects/interchange/en/stable/using/collections.html)

### 4.4 文件级改造与测试归属

下表路径相对现有 `materials_simulation/`。新增模块名在实施时确定，不预建空目录。

| 现有文件 | 具体改造 | 主要验收 |
|---|---|---|
| `materials_sim/schema.py` | v1 读取与拟议 v2 解析分开；拆模型/模型包/组成/场景/协议/分析；工程预算不写成永久科学限制 | 未知字段、重复引用、单位、数量和冲突检查；v1 不伪造缺失字段 |
| `materials_sim/build.py` | 保留协调；`snapshot()` 冻结实际传递依赖而非一律复制水库；`compile_stage()` 的 GROMACS 部分移入引擎职责 | 原模板不改，资产完整；多构建器一致交接 |
| `materials_sim/topology.py` | GRO/展开 TOP 解析留在格式侧；分离全局身份与组成检查；SOL/中性/显式电荷按模型和场景校验 | 顺序、数量、重复名、三斜盒及模型所需属性 |

| `materials_sim/execute.py` | 移出 mdrun 参数和 GROMACS 日志/检查点解释；保留预算、循环、状态、封存 | 实际目标完成、中断恢复、非 prod 终点、单写者 |
| `materials_sim/gromacs.py` | 组织 GROMACS 输入生成、预处理、运行、检查和恢复；不认识材料名字 | 原 ZIL 回归和同 TPR 恢复不退化 |
| `materials_sim/state.py` | 分开读取、完整性、执行兼容；按实际阶段清单校验；源码身份覆盖新增子模块及外部工具 | 升级后旧结果可读，执行不无条件 append |
| `materials_sim/analysis.py` | 调度与水化算法分开；从产物记录选择阶段/轨迹；独立分析状态 | 非 prod 分析、无水任务、失败不重跑 |
| `materials_sim/files.py` | 保留路径、哈希、原子写和锁，按新交接补测试 | 中文/空格路径、移动新 Run、冻结输入隔离 |
| `materials_sim/cli.py` | 查询按所选工具和能力执行；`--through` 按解析阶段 ID 校验；新增能力查询须有实际记录 | 查询不构建、不运行；不能使用虚构命令 |

### 4.5 引擎接入策略

M1 先分清 GROMACS 编译、运行、评估与通用编排；使用简单模块和函数，不先创建抽象工厂。M5 引入真实 LAMMPS 输入、结果及恢复实现，两者共用运行记录但不共用检查点语义。

后端需要实际实现：环境特性检查、生成有效输入、执行/停止、解释结果、判断完成、检查恢复条件。模型包与协议共同决定允许后端；场景不按材料名称硬编码引擎。单个体系先由一个能完整表达模型的引擎运行，不把 GROMACS/LAMMPS 实时耦合作为本次目标。

LAMMPS 须冻结所用势文件、有效输入及单位制，不假定一个 restart 文件自动包含全部继续运行信息。两个后端分别验证续跑和轨迹身份；跨引擎转换不等于跨引擎检查点续跑。

### 4.6 最小资产组织

拟新增 `library/`（组分、模型和模型包及来源）、`protocols/`（独立协议）、`experiments/`（真实基准与实验配置）；仅在有内容时创建，均归属 `materials_simulation/`。模型复制须保留来源与许可，不移动旧输入。已有 `examples/` 中 v1 例子作为迁移基线保留。

研究参数、可追溯模型文件可以进入源码管理；大轨迹、日志、检查点、环境和缓存不放源码。先保持可导入包布局，不捆绑迁到 `src/`、建立 Git 仓库或发布安装包。

## 5. 模型包、组成解析和专用构建

### 5.1 模型包是完整性硬门槛

一个模型包必须记录以下适用信息，缺项不以默认值补齐：

1. 组分模型版本与内容哈希，分辨率、覆盖化学状态及用途。
2. 势函数形式、全局参数约定、单位、原子类型命名空间、键合项及特殊项。
3. 电荷模型、水模型、排除规则、1–4 缩放、非键组合规则或显式交叉参数。
4. 多体模型的完整元素集合、域和贡献；不把两两参数表当成所有多体相互作用的证明。
5. 参数化工具、原始来源、许可、间接依赖、适用引擎和必要数值设置约束。
6. 验证实验、原始证据、温压/组成/表面范围与已知不足。已有物性验证不能无限外推。

预检分三种结果：缺失/冲突则阻止积分；完整候选只允许受限工程检查或明确的模型验证实验；在记录范围内有证据的模型可进入相应研究协议。软件不自动证明新模型的科学有效性，不允许一个布尔开关跳过完整性检查。

全体系参数必须可共存，不把多个 `.top` 文本直接拼接。GROMACS 首版仅处理核查过的拓扑子集：单一一致 defaults、正确 include 顺序、同名类型完整语义相同才共享；宏不明、类型冲突和未支持条件 include 明确失败。原生预处理与平台检查共同负责，禁止提高 maxwarn。

对金属/无机多体模型不套用分子 defaults 检查；专门验证势覆盖与交叉贡献。LAMMPS 文档明确提示，不应以 hybrid 任意补齐缺失的多体模型。[LAMMPS hybrid 限制](https://docs.lammps.org/stable/pair_hybrid.html)

对有机—无机界面，优先评估适合选定材料的 INTERFACE 等模型及具体兼容变体，不把“采用 IFF”当成普遍兼容保证。[Heinz 等，2013](https://pubs.acs.org/doi/abs/10.1021/la3038846)

### 5.2 组成解析：请求、离散计数和实际结果分开

- M3a 先实现正整数分子数量，包括选定混合溶剂；不使用的组分由用户省略，显式 count=0 仍拒绝，不静默删除实例组。实例组 ID 唯一，同一模型可在不同区域重复出现，不误判为重复组分。
- 同一实例组的重复定义、非整数计数、非有限数、冲突单位和过约束输入直接失败。不同区域计数分别核对后再汇总。
- 既有回归可显式使用填充剩余空间的水策略；该策略不是精确溶剂计数。水仍是正式登记的组分，不能藏在模型包外。
- M3b 是配比/浓度解析扩展：声明摩尔/质量基准、总数量或体积约束、温度相关体积含义、聚合物以链还是重复单元计量，明确整数舍入与误差。
- 如果按总质量与目标密度推导初始体积，应纳入全部组分和端基质量；不能按水密度直接计算复合体系实际密度。密度构建估计不等于平衡测量。
- 记录请求值、解析计数、舍入偏差、构建后数量和实际配比；NPT 后体积变化导致的浓度变化另报。
- 显式的数量、盒子与密度冲突不静默归一化；不擅自减分子、扩盒子或补反离子。带电分子允许作为组分，首批分子体系净电荷策略仍为明确中性及模型规定的舍入残差检查。

### 5.3 分子液体与区域装配

Packmol 已作为 M3 当前子集的多组分液体/区域装配工具，本机已验收 21.2.3，代码要求 ≥21.1.0 的文件输入接口和正交周期装箱。`gmx insert-molecules` 可用于明确的小型过渡案例，但不是聚合物、固体和界面的统一构建器；工具缺失时不能静默换构建算法。Packmol 支持分子数量和区域约束，其原生周期装箱范围需按安装版本核查，不能因框架有 3×3 晶胞就假设它支持任意三斜装箱。[Packmol 手册](https://m3g.github.io/packmol/userguide.shtml)

每次构建：解析计数与稳定实例顺序 → 核对模板映射 → 冻结装填种子、距离约束和尝试预算 → 装配 → 按声明策略填充 → 核对最终数量、重叠、区域和全局映射 → 引擎预处理。少装一个分子也失败；尝试耗尽停止，不通过换随机种子掩盖系统问题。

`gmx solvate` 保留为已存在的显式水填充路线；原模板、填充前后坐标与拓扑分开保存。其实际水数应从结果核对，不能用截掉部分水的方式冒充浓度构建。[GROMACS 加水文档](https://manual.gromacs.org/current/onlinehelp/gmx-solvate.html)

### 5.4 聚合物构建与参数化

先选一个具体家族，记录重复单元结构、连接位点、端基、立构、序列、聚合度/分布、电荷状态及研究问题。模板可复用的前提是连接和端基处参数齐全，不能直接复制游离单体电荷/键合项。

优先评估 Polyply 的构建块/连接规则与坐标生成；按选定材料覆盖和验证结果确定是否使用。mBuild 可承担简单层级结构；不同时引入多个功能重复的构建器。Polyply 也需要相应参数构建块，不是任意化学的自动参数开发器。[Polyply，2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC8748707/)

单链验收先检查重复单元和端基原子数、连接、参数覆盖、净电荷及身份，再进入单链溶液、多链溶液、与小分子混合和熔体。熔体的装填、排斥引入、致密化与松弛单独设计，检查局部和链尺度结构，不把消除重叠或密度平稳当作链已平衡。[Auhl 等，2003](https://arxiv.org/abs/cond-mat/0306026)

RadonPy 用于借鉴或按范围适配非晶聚合物制备、平衡判断与性质流程，不整体替代平台；其论文主要验证范围不能直接外推到任意复合体系。[RadonPy，2022](https://www.nature.com/articles/s41524-022-00906-4)

### 5.5 晶体、非晶、表面和颗粒

M5 以 ASE 为基础评估晶体构建、晶胞与结构交接；复杂晶面/终止选择需要时再接 pymatgen，不重写成熟晶体几何算法。[ASE](https://docs.ase-lib.org/)、[pymatgen 表面构建](https://pymatgen.org/pymatgen.core.html#pymatgen.core.surface.SlabGenerator)

晶体记录来源、晶型、基元、晶胞、超胞和缺陷；几何结构不等于已分配势参数。非晶无机材料和玻璃态聚合物各有制备路线、热历史与结构验收，不以晶体加热短测替代。

M6 记录晶面/表面终止、羟基化或其他官能化、电荷、颗粒尺寸/形貌、是否固定/约束及研究范围；体相结构简单切割后不能自动当成可用于溶液的已验证表面。导入成熟表面模型也须完整保存来源。

界面构建先确定固体/颗粒、可填充区域及排除区，再填充溶剂和其他组分；记录几何约束与实际分布。非共价吸附和共价接枝分开，首批不实现动态成键或交联。单独模拟固体通过，不代表其与聚合物/水的交叉作用存在。

## 6. 场景协议、分析与科学检查

### 6.1 场景规则

配方与场景分开；ZIL、CAT/ANI 等名称不得成为核心分支。预构建体系导入是一种输入方式，不是新物理场景。场景须分别描述物理边界、初始/目标结构，以及引擎数值实现；真空、薄膜真空层和完全周期体相不能混写。

| 场景 | 协议重点 | 必需的适用检查 |
|---|---|---|
| 分子液体 | 松弛、热化、体相密度调整与采样 | 计数、电荷、能量、温度、密度与分布 |
| 聚合物溶液 | 完整链与溶剂化、构象松弛 | 连接、跨周期重建、链尺寸与构象采样 |
| 聚合物熔体 | 多链装填、致密化、材料专属平衡 | 局部结构、内部距离/链尺度统计、慢松弛 |
| 晶体 | 晶胞/原子松弛及热化 | 晶格、应力、结构稳定性和势模型参考 |
| 玻璃/非晶 | 明确制备和冷却/退火历史 | 结构、密度、速率/历史影响，不宣称普适平衡 |
| 固液界面/颗粒 | 分区装配、必要约束、分阶段松弛 | 表面状态、可动区域、分层结构与交叉模型 |

温控/压控分组与自由度、固定原子、约束、水模型和时间步必须兼容；不对真空方向套各向同性压控。slab 的周期性、长程静电和晶胞自由度联合校验，支持范围以实际引擎版本为准。[LAMMPS slab 处理](https://docs.lammps.org/kspace_modify.html)

### 6.2 阶段契约

- 阶段有稳定且唯一的 ID 与类型；同一种类型可出现多次。不根据 ID 是否叫 em/nvt/prod 决定物理行为。
- 每阶段明确来源、结构/速度/检查点状态继承、生成速度的种子、时间/步数原点及目标终点；不同引擎的 restart 语义由后端解释。
- 记录积分/最小化算法、步长、温压/应力、约束、温控/压控、允许变动的晶胞方向、模板哈希与最终有效设置。
- 记录输出频率、粒子选择、坐标/速度/力/能量/盒子需求及单位。阶段产物带角色、格式、哈希、映射、时间信息和所属引擎，而不是只有文件名。
- 阶段完成由适用标准判断：最小化达到规定力标准；动力学达到实际步数/时间和必需输出。阶段 ID、最终阶段和分析来源互不硬绑定。
- 首版线性执行；重复退火可展开为不同 ID 的明确阶段。质量不足时停止并报告，或在已经授权的有界规则下创建追加/派生任务，不能无限延长。
- 工程短测、模型验证、正式采样使用独立目的与协议。注册新目的需要对应校验、测试和资源约定，不能只删除当前 smoke 上限。

### 6.3 分析任务与产物绑定

分析请求显式引用一个已封存的阶段产物或明确有序的产物序列；M1 先支持完成 Run 内的单个已完成阶段，不承诺活跃轨迹并发分析。不能固定读取 `stages/prod`，也不能因最终阶段重命名而失去分析。

- 分析任务可为空，但构建和执行 QC 必须运行。
- 水化作为独立算法保留；M3 增组分接触和基础分布，M4 增链尺寸/构象，M5 增选定结构检查，M6 增密度剖面和界面接触。
- 启动前反向检查所需轨迹数据；缺速度、力、质量、键、周期信息或选定原子不能推测补全。
- 每个 AnalysisRun 冻结原始轨迹/映射、阶段来源、配置、版本、窗口、去平衡段和归一化；改变阈值或窗口生成新分析。
- 链尺寸先验证整体重建；动力学量处理位移展开、时间连续性和续跑重复帧；局部最短距离不等于链整体恢复。
- 界面密度与接触有区域、面积/体积及参考系约定，不把均匀体相统计直接套到薄膜/颗粒。接触计数不等于吸附自由能。
- 分析失败只影响该分析状态，不改变 MD 完成状态，也不隐式重跑。新分析不能改写原模拟证据。

### 6.4 三层验收，不把 completed 当成可信

1. 工程：参数与结构完整、过程结束/可恢复、目标步数、文件与身份一致。
2. 数值物理：按模型与协议检查积分、能量、约束、温控/系综、结构稳定性等；不是所有场景执行同一套 NVE 测试。[Merz 与 Shirts，2018](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0202764)
3. 研究证据：目标量平衡/稳态、相关时间、有效样本、独立重复、不确定度、尺寸/历史影响及适当实验或文献基准。统计误差与模型偏差分开，短测不填造独立样本量。[Grossfield 等，2018](https://livecomsjournal.org/article/5067-best-practices-for-quantification-of-uncertainty-and-sampling-quality-in-molecular-simulations-article-v1-0)

每一模型/场景在运行前填写观察量、算法、参考范围、容差依据、重复设计、预算和停止条件。没有实际证据只可记为计划或未评估；温度/密度平稳不能单独证明所有慢变量收敛。

## 8. 历史 Run、恢复与长期存储

沿用[兼容性规则](../ai/COMPATIBILITY_POLICY.md)，只保护实际持久化资产和真实调用方，不维护无期限的双套新运行入口。

| 操作 | 校验与写入约定 |
|---|---|
| 查询状态/报告 | 按版本读取，展示原实现与证据可用性；当前源码不同本身不阻止读取 |
| 验证完整性 | 冻结输入和封存输出继续按哈希检查；缺失/损坏不被兼容代码吞掉 |
| 旧轨迹新分析 | 数据契约通过后写独立 AnalysisRun，记录当前分析实现；原 Run 不修改 |
| 未完成阶段续跑 | 同一物理输入、有效引擎检查点、合法状态与输出连续性，且执行兼容已验证 |
| 改模型、协议或延长已完成目标 | 新 Run，引用父来源；不重开旧完成态 |
| 完成、终止失败、取消、不确定状态 | 不原地重开；需要时在授权及专项验证后建立派生任务 |

M1 实施前保存本轮涉及的核心源码、测试和配置的带哈希版本快照；不复制全部科研数据。v1 原有身份定义保留，不重算为 v2，不伪造其缺失的物理/验证字段。原临时轨迹丢失只能报告缺失。

M1 已把实现身份改为递归扫描包内 `.py`，包含适配器和分析代码；字节码不计入。历史读取不做“当前代码全相同”要求；当前只执行 v2，执行兼容仍严格，不能添加 force 绕过。旧 v1 执行需要其原代码，当前仅保护只读与外部重分析。

GROMACS 续跑保护原 TPR 和输出校验；LAMMPS 保护其有效脚本、势文件、单位及 restart 约定。后端分别提供可执行的恢复契约和真实测试，不把两个引擎的 checkpoint 当成同一格式。

硬杀、断电、磁盘不足需区分进程、锁、状态、检查点和封存边界；先只读诊断，不自动删锁或改状态。未实施的灾难恢复和父 Run 派生应在能力表中保留未实现标记。

正式 Run 使用明确稳定的外部存储根，不能把 `/private/tmp` 当成科研归档。文件位置与科学身份分开；源码/输入与轨迹/日志/检查点分开。当前 attempt 完整复制输出的方式可保留于小测试，大轨迹前需设计有校验的分段和产物封存，不通过删证据节省空间。

核查 ZIL、CAT、ANI 和水的坐标/拓扑/来源；建立独立模型与协议、模型包及来源映射。固定构型导入用于迁移回归，不能冒充自动组装。

退出：两套既有案例使用同一入口完成短程闭环，无按名称分支；同坐标、同有效参数的迁移数值检查通过，旧参数与 runner 不变。候选模型不因工程闭环自动新增科学验证范围。

### M3：多组分液体实用版

状态：**部分实现，不得标整体完成**。已交付 T3/T4/T5 和 T6 当前子集：四种已有模型自动装配场景、真实恢复、组分接触、能力查询及负例；水以 bundle 覆盖的填充策略加入，记录实际数量，不是独立溶剂模板共装。公共参数合并仅覆盖显式 GAFF 有限分子，不是任意材料模型兼容器。详见 [M3 子集验收](../../docs/validation/2026-09-14__m3-packing-subset-acceptance.md)。

M3a 必需：Packmol 路线的按数量装配、实例/区域映射、全局参数检查，多溶质水溶液及一组选定混合溶剂；去水依赖回归、非水化分析、真实能力查询和负例。

### M5：真实晶体固相与 LAMMPS

前置：选定一个适合固相基准的晶体及完整势模型、参考结构/性质、单位和协议；不由程序随意选择材料。批准 ASE/LAMMPS 环境后执行。

### 10.3 工程与科研预算分开
