# 分子模拟失败诊断

读取[根规则](../../AGENTS.md)、[模拟规则](../../src/materiasim/AGENTS.md)和目标案例/Run 的真实入口。诊断目的是定位原因和下一步，不是通过修改现场让错误消失。

## 保全现场与辨别状态

1. 确定用户指定的 Run/阶段、命令、工作目录及正在运行还是已结束；不要仅因日志暂时不更新判定卡死。
2. 先读取实际存在的输入清单、状态、命令日志、引擎 stderr/log 和输出元数据；旧 runner 文件名可能不同，不强制套用新方案的 manifest 格式。
3. 核对原始错误前后的上下文。Markdown 报告是摘要，原始日志和输入身份是诊断依据；记录矛盾与缺失，不回写现场来消除差异。
4. 不停止进程、删除锁、清理输出、修改状态、重新参数化或重新启动。需要这些动作时先说明具体原因与范围，并确认属于已授权修复任务。

## 按证据缩小问题范围

| 检查层 | 核查内容 | 不能据此直接断言 |
|---|---|---|
| 环境/入口 | 实际解释器、工具版本/路径、工作目录、参数解析、文件权限 | 找到可执行文件就代表整个协议可用 |
| 输入/参数 | 缺文件、哈希、间接 include、原子数/顺序、电荷、参数项和约束 | grompp 能通过就代表模型物性正确 |
| 构建/数值 | 初始重叠、几何、能量/力、错误首次出现阶段、步长与实际参数 | 一条 LINCS 或 NaN 消息就唯一证明某个原因 |
| 执行/恢复 | 目标/实际步数、检查点身份、输出连续性、磁盘、终止信息和单写者 | 有 cpt/gro 文件或退出码为零就代表完成 |
| 采样/分析 | 时间范围、平衡剔除、原子选择、单位、周期处理、缺帧、重复与慢观察量 | 密度平稳就证明链松弛或吸附平衡 |

优先找最早有证据的偏离，区分根因与后续连锁报错。正常读日志、检查文件/哈希和现有只读检查可执行；会生成文件的辅助检查须使用隔离的临时位置且符合任务授权，不改 Run。

## 提出最小验证或修复建议

- 把结论分为已确认、最可能原因、仍需排除的替代原因和缺少的证据；不要把主观把握程度写成统计置信区间。
- 建议一个能区分原因的最小检查，说明是否只读、会产生什么输出及资源需求；不要默认开启全量 MD。
- 不建议用提高 maxwarn、忽略约束警告、自动换力场或删除断点输出来“修好”。科学参数需要变更时说明会形成新的实验/Run 及验证需求。
- 如果用户也授权修复，修复前保留证据，按所属模块规则做相关测试；已完成的物理阶段不因分析失败而重复计算。

## 交付内容

简要列出运行/阶段、实际状态、关键证据位置、原因与替代解释、最小下一步，以及哪些操作尚未执行。缺少必要证据时直接说明无法定论。不要把诊断建议写成已实施修复或已完成科学验收。
