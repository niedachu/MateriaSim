# 分子模拟研究

先复用已有证据，再决定需要什么计算。读取[根规则](../../AGENTS.md)、[模拟规则](../../src/materiasim/AGENTS.md)及任务所属案例的 README/配置/实际入口。以下流程不授予新增计算、安装或改代码权限。

## 1. 确定问题与已有能力

- 分清咨询、研究设计、结果比较和已授权执行；用户只问方案时，不生成 Run、不启动模拟。只读分析可以继续。
- 搜索已有组分参数、协议、案例、报告和失败记录；没有 catalog 时使用文件搜索，不调用虚构的 discover/check 命令。
- 将能力标为已有可用、需要验证或未实现。新聚合物/纳米材料不能从“已有 GROMACS”推断为已支持。
- 明确哪些是文献事实、历史运行记录、当前实测或待验证假设；版本不明、资料冲突和证据缺口单独说明。

## 2. 固定最小研究定义

按任务规模记录必要信息，不为了小问题建立完整研究管理系统：

- 科学问题、已有基线、拟比较变量、组分和参数来源。
- 分辨率、组成、边界、协议、观察量及单位；参数验证与正式采样的用途区分。
- 对照和重复设计、实际构建/速度种子、预期结果及可以否定假设的结果。
- 粒子规模、时长/步数、计算与存储预算、停止条件和失败条件。

沿用已有课题及实验定义。仅改变已声明变量或种子时记录新 Run；改变研究问题、模型含义、观察量定义或比较设计时，显式修订实验定义及其来源，不能悄悄沿用原结论的适用范围。不要另造 Program/Study 身份系统来取代项目中的实验/Run 约定。

## 3. 检查并按授权执行

- 按模拟规则核对参数兼容、冻结依赖、坐标/拓扑身份、输出需求和资源。候选模型的验证实验可以建立证据，但不豁免参数完整性检查。
- 从真实 README 和参数解析器核实入口、工作目录及输出语义。新平台未实现前沿用已存在的案例能力；不把升级方案中的示例命令当成当前接口。
- 特别核对是否会启动正式长协议：ZIL 的现有生产入口没有 smoke 开关。用户要求“小量跑通”时，不直接调用完整生产入口代替短程验收。
- 执行只使用范围内预算和独立输出位置；缺必要权限、输入、工具或短程路径时报告具体阻塞，不安装替代软件、不无限重试。
- 已实现研究包命令见[研究使用指南](../../docs/guides/research.md)。先用 `materiasim research validate/plan` 查看显式条件和种子；plan 默认只预览。执行必须指向冻结计划及明确外部目录；恢复需 `research run --resume`，不删除登记或失败 Run 来重复提交。
- 保存实际输入与产物引用；运行不修改旧报告、原始数据、知识库或索引。重分析另存，不手动补写历史验收记录。

## 4. 比较与交付

- 先声明比较中有意变化的条件，再检查其余条件、模型和观察量定义是否可比；跨分辨率结果分别解释。
- 报告所有声明的候选、重复、失败和采样不足。区分数值贯通、时间块稳定、独立重复与科学验证。
- 每项结论链接明确输入/Run/分析产物，不用 `latest`、`best` 或只有终端摘要作为正式证据身份。
- 给出结论、限制与一个有价值的下一步；用户没有要求持续研究时，不自动展开新的计算轮次。

遇到运行异常，读取[失败诊断技能](../simulation-diagnostics/SKILL.md)。比较结果本身不授权改变模型、正式参数或研究目标。
